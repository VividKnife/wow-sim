# 手机运行时资料优化（2026-09-29）

## 实现

源资料保留在 game-data/data，用于导入、审计与构建。`scripts/content-source` 是构建期源适配器；浏览器和服务器的规则目录只读取编译产物。

`npm run data:compile` 先执行运行时编译，再生成统一内容清单。编译阶段完成表合并、索引、怪物空间归属、物品来源和手册掉落分类。去掉运行时不需要的全世界刷新点原表、重复副本 SQL 表、手册来源路径，使用共享记录、字段 schema 和默认值编码。原始记录的字段顺序、undefined、表合并顺序均有对照测试。

浏览器入口先读取 gzip 启动包，然后按角色与队伍职业读取预取包；其余资料按实际依赖补载 8192 条记录的分片。职业预取是构建时对该职业合法种族、1/60 级角色界面的访问采样，不是完整依赖声明；未采到的装备、任务、怪物、NPC 养成依赖仍由分片机制完整覆盖。后台 NPC 可以使用其他职业，不能只留下玩家职业而悄悄改变养成结果。

使用普通对象和可枚举 getter 按访问解码，不使用 Proxy，快照仍可 structuredClone。正在执行的模拟片段先保留原状态，暂存对 UI 和策略 Worker 的输出；遇到缺失资料时整段回滚、异步下载，然后从相同状态和随机数重试。下载失败暂停并报告，不使用空表、默认伤害或部分结算结果继续游戏。切换角色与下载完成之间的竞争也有测试。

版本号覆盖编译数据和启动/界面预取的构建输入。服务只提供当前版本资料，URL 绑定版本并启用一年 immutable 缓存；不同版本拒绝混用。Docker 镜像包含所需分片，不依赖部署机器外部的原始文件路径。

## 预算及边界

- 解码热缓存：估算 8 MiB，弱引用复用仍在使用的对象；按创建顺序淘汰。
- 动态原始分片：估算 32 MiB；当前模拟片段的依赖固定到提交/回滚补载完成，工作集可暂时超过预算。
- 启动包与最多九个职业预取包常驻，重叠记录按 ID 去重；上述缓存预算不是浏览器总内存上限。
- 历史战报：最多 20 场且总序列化记录不超过 1 MiB；当前战斗与最近战斗的规则/结算数据保持完整。
- 手机继续使用单个模拟 Worker，避免额外策略 Worker 重复加载规则。没有禁用团本，没有把战斗计算迁移至云端。

## 本地测量

| 指标 | 优化前 | 当前 |
|---|---:|---:|
| 独立 esbuild Worker（minified） | 约 94.83 MB | 2.00 MB |
| 完整运行时资料 JSON | 约 94.07 MB 原始 bundle 输入 | 49.75 MB 编译产物，仅 Node 直接读取 |
| 生产 webpack 最大 JS 分片 | 80.265 MB 共享资料块 | 0.844 MB |
| 单人法师冷启动资料请求 | 整包 | 4 次，共 5.63 MB gzip |
| 团本冷启动资料请求 | 整包 | 15 次，共 11.76 MB gzip |

单人、团本数字来自真实 browser Worker 的 VM 测试，包含启动、职业预取及第一轮实际补载。不同存档会有不同依赖。这不是整页总下载量，不含模型、纹理与 UI 资源。桌面 Node 导入后强制 GC 的堆约 211 MB，原研究约 360 MB；Node 与 iPhone 的 GC、资源预算不同，不能据此推算手机总内存或宣称已证明崩溃原因。

## 验证

- 编译目录与源目录逐表/逐字段摘要对照、翻译和空间路由对照。
- 单人和团本真实 Worker 的完整持久化检查点与同步引擎一致。
- 冷加载失败不提交部分结果；加载时切换存档不串角色；启动包先失败、开始消息后到达仍报告错误。
- gzip 内容端点、版本不匹配、路径和索引边界检查。
- 缓存与战报预算、structuredClone、缺失记录补入后重试。
- TypeScript、生产 Next 构建，以及独立 PostgreSQL 的账号/存档/服务端集成验证。
- 本地浏览器单人狩猎、多场战斗及拾取，390×844 尺寸截图检查。外观服务出现过模型请求超时；该外部服务不属于本次数据包加载链路。

全量玩法回归和优化前基线对照另见最终验证记录。最终手机稳定性仍需 iPhone Edge 实机连续游玩验证。
