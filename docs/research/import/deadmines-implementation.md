# 死亡矿井实施状态

## 来源

`import-deadmines.py` 从已审阅的外部研究文件生成 `apps/web/data/deadmines-reference.json`，保存四个输入文件的 SHA256、上游固定提交和来源清单。入口条件额外读取相同固定 SQL 的 `areatrigger_teleport` 第 78 项并验证压缩包哈希：最低等级 10。

- 数据库：`22b51464f1625f6ef6275771de1f5466c6f5d19e`。
- 社区内核：`8ec338a1704e7dcb1c0213eb7ed58f9231ade40f`。
- 58 个路线节点，198 个唯一战斗/事件 GUID，另有 9 个环境刷怪点。
- 52 个随机模板点每次副本只选一个模板；约翰森出现率 20%。怪物等级和基础属性一并保存，重新进入不重新抽取。
- 节点分组、推进顺序、按坐标中心估算的行走时间均为 2D 改编，没有声称复刻原版导航网格、碰撞、楼层视线或真实拉怪组。

## 已接入引擎

- 进入/离开/继续副本、可选支路跳过、逐 GUID 击杀状态和唯一推进。
- 原版入口最低等级与五人存活队伍校验；五人要求是本游戏的小队规则。
- 首领死亡开门条件及后续原有巡逻 GUID；火药箱、实际消耗一份火药、开炮 500ms 开门、15 秒第二次警报。
- 斯尼德伐木机死亡 3500ms 后，独立斯尼德加入同场战斗；真正的斯尼德死亡才解锁后续巡逻。
- 全队补给、法力五秒规则、分职业精神恢复、牧师复活和团灭恢复；实例心跳中断不推进时间或随机状态。
- 范克里夫信件掉落、原地接受物品发起任务、离开后真实旅行至交付地点、交付一次。

## 掉落修复依据

[LootMgr.cpp 463–496](https://github.com/cmangos/mangos-classic/blob/8ec338a1704e7dcb1c0213eb7ed58f9231ade40f/src/game/Loot/LootMgr.cpp#L463-L496) 区分普通、条件和任务专属掉落。任务起始物品不能错误地要求“已经接到它开启的任务”。目前遵守：

- 条件类型 6 比较队伍阵营，当前人类角色为联盟 469。
- 起始物品默认在任务已接受/已交付时被过滤，可重复任务交付后可再次获得；`ExtraFlags & 0x02` 忽略该状态限制。
- 最低等级检查属于接任务，不属于起始物品的掉落资格。
- 负掉率任务专属行仍要求相应任务需求；不再仅凭物品属于任务类别，就过滤正常正掉率行。

其他首领衔接和信件奖励测试使用明确的死亡状态夹具，验证时序、存档与奖励链路，**不算完整首领战或正常通关**。
