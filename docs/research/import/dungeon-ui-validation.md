# 死亡矿井界面验证 — 2026-09-16

## 可操作流程

- 西部荒野世界页提供入口卡片，到达死亡矿井入口后检查五人队伍、最低 10 级、存活和空闲状态。
- 副本内替换野外交互为路线面板：当前敌人及等级、58 段路线进度、可选支路、机关、队伍生命和法力。
- 每次推进先旅行，实际开战后自动打开已有战斗窗口。结束后等待玩家休整、装备或继续。
- 背包满、待拾取、队员倒下、恢复中等阻塞原因可见；火药箱和火炮使用实际引擎命令。
- 提供小队坐下恢复、法师制造补给、牧师单人复活、倒下成员返回尸体、离开并重返本次副本。
- 修复队长死亡时 `rest` 被空闲校验拒绝的问题，允许存活牧师先恢复。复活按钮与引擎允许的活动类型一致，野外挂机两次拉怪之间也需先停止再复活。

## 实际浏览器结果

使用 `node scripts/serve-dungeon-preview.mjs` 启动独立 localhost:5174 测试页面。它调用真实引擎与生产组件，不连接 API、不读取或更改用户存档。18 级、已学技能、补给与特殊机关起点均为明确标记的夹具，不作为自然升级证据。

1. 从入口进入、旅行、首组两名矿工战斗自然结算，五名成员存活，路线从 0/58 到 1/58。
2. 退出显示已保存 1/58，再进入仍是「矿道前哨」，配置和进度没有重抽。
3. 火药守卫已清除夹具：点击拾取后进入火炮前矿道；火炮夹具：装填期间不能重复操作，500ms 开门后显示铁门警报守卫。
4. 队长死亡、牧师空蓝夹具：小队休整消耗一份饮水；法力充足后复活按钮可用；复活有 10 秒读条，完成后队长存活并能继续推进。
5. 390×844 窄屏：页面滚动宽度 375（视口 390，滚动条占位）；四个面板 clientWidth 与 scrollWidth 均为 345，无横向溢出。火药原版图标加载成功，无缺图。

测试期间另有角色样式文件写入造成短暂热更新加载错误；资源落盘后重新加载，已确认没有开发错误覆盖层。测试后恢复视口，独立测试页面关闭。

## 数值与玩法观察

额外运行同一种子 283 的连续路线夹具，18 级玩家和同级、按玩家低装备水平招募的四名队友，未修改敌人生命、伤害或命中：

| 遭遇 | 含行进/休整的模拟时间 | 结果 |
| --- | --- | --- |
| 入口矿工 | 22 秒 | 两只击败、五人存活，坦克余 347/398 生命 |
| 矿道前哨 | 114 秒 | 五只击败、队长死亡，其余四人存活；治疗剩 101 法力、队友法师剩 14 法力 |

这证明连续推进需要恢复和仇恨/控制处理，也提示低装备的默认策略有风险。没有据此削弱怪物。下一步应核对多目标坦克行为、控制策略与对应版本怪物属性公式，再用自然成长装备重跑。

## 资源与边界

迪菲亚火药 5397 图标来自固定 Gethe 2019 Classic 预发布快照，Git blob 与 SHA-256 校验见 `deadmines-items-assets/manifest.json`。当前 Classic tooltip 仅用于中文名和图标身份，不导入其数值。

目前仍缺完整 58 节点正常通关、真实角色自然 1–20 级全流程、最终数值对照和部署验收。五人战斗画面仍采用纵向滚动分行，多目标手机战场需继续压缩和优化。
