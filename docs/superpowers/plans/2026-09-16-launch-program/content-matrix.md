# 世界、人物、副本与运营内容清单

本清单定义目标范围与拆分粒度，不表示记录中的地图/首领已经完成。区域名用于产品范围登记；实际 Area/Map/Quest/Creature/Item ID、等级、刷新和数值由冻结来源生成，并逐项核对。不要依据下表的排期分组修改原始任务等级。

## 1. 完成状态与计数

每个条目依次经过 `Catalogued → Reachable → Functional → Integrated → Verified → Released`。额外可用 `Excluded`，但必须有版本证据与范围理由，不能用来隐藏实现困难。

每个实体记录：稳定 ID、来源 ID/提交/校验值、规则版本、开放阶段、地区、依赖、实现处理器、证据状态、适配说明、测试 ID、负责人和发布版本。

报表分别给出目录覆盖、获取可达覆盖、机制实现覆盖、证据验证覆盖、发布覆盖。分母包含冻结首发目录中所有必选条目；仅过滤公开记录的阶段外和未实装内容。目录记录、地图点、任务步骤、遭遇、唯一技能都分别计数。

### 单个区域的统一验收包

1. 正确大陆与坐标投影、边界、入口/出口、墓地、室内/室外标记、地形标签。
2. 版本内 NPC、怪物、对象、刷新点、阵营/敌对关系；稀有与巡逻按来源处理，未知路线明确标记。
3. 所有本阶段区域任务的接取、前置、目标、交付、放弃/重接和奖励；跨区域链必须连接，不能凭空发任务物品补洞。
4. 商人、训练师、专业、旅店、绑定点、飞行点及修理；适用于该地区的功能均可用。
5. 草药/矿物/鱼群/剥皮、材料与掉落；既有专业数据与来源区域对应。
6. 正常角色能进入、完成任务、获得对应等级的装备与补给、离开；不存在断路或仅能靠 GM 传送的服务。
7. 联机中的目标信用、资源归属与队伍活动租约；个人离线挂机不得同时占用共享区域刷怪收益。
8. 来源、数据校验、正常命令回放、手机地图截图和未验证项清单。

地图阶段目标允许拆成“结构及基础练级”与“完整内容验收”两个交付，但只有第 8 项完成后才标记 Verified。特殊任务机制单独交机制工单，区域作者不能各自写不同护送/载具/事件引擎。

每个副本包含所有首领、必经怪组、可选首领、稀有/分支、任务、钥匙、掉落、重置/锁定和死亡恢复；不能只做尾王。副本任务奖励与正常物品掉落分别登记。

长期伙伴任务装备按每个合法角色分别发放，每人有独立资格与领取凭据；副本首领掉落不因此乘以人数。该最新要求及共用任务入口的具体建议见[队友设计](../../specs/2026-09-16-companion-models-design.md)。

### 通用遭遇协议

遭遇按 `prepare → active → success/failure → settlement → checkpoint` 生命周期执行；支持时间、血量、死亡、交互条件触发，怪物召唤、阶段、免疫、环境效果、仇恨切换、目标限制和战利品表。

能力不足时新增机制处理器并附单元用例，再让所有遭遇复用；内容包不能自行操作数据库或直接修改角色钱包。所有随机抽取和事件顺序记录在实例日志中。

玩家市场后置不等于交易资产安全后置。即使 G1 只有模拟市场和直接交易，仍要消除无限补料→制造→收购的无风险增金循环、分解回路和 AI 配发物品变现。

双主要专业为用户新要求；烹饪/急救/钓鱼是否作为不占位生活技能，依队友设计中的建议处理。个人专业产能是玩法目标，需要计入材料供给和金币收支；不能为了账本统一而抹掉执行者身份或把个人收益改成全队技能同步。

## 7. 横向资产与体验

- 所有 NPC/敌人/物品/技能/天赋按实体 ID 映射图标；地图底图和覆盖层的坐标一致，缺失资源明确降级。
- 音效有开关/音量和移动端交互解锁；重复战斗音效节流；不能因为资源缺失阻塞战斗。
- 人物模型属于表现，核心游戏不依赖第三方模型站点可用。需要本地可发布资源或可靠降级。
- 任务文本、技能说明、物品效果、阻止原因和错误提示中文可读；记录数值和表现的不同来源。
- 键盘、触屏、色盲可识别的状态、最小触控区域、加载和重试状态作为组件统一标准。
- 离线收益展示有时间区间、获得/消耗/停止原因，支持用户核对；队友战斗、任务和掉落可回看。

## 8. 不计入本轮“完整经典旧世”的内容

外域/诺森德、血精灵/德莱尼、死亡骑士/武僧等后续职业、飞行坐骑、卡拉赞等后续团本、探索赛季符文、正式服系统和真实 3D 开放世界不在范围。纯后台测试区域不必做成可玩地图，但从来源清单中剔除时要登记理由。

后续运营活动采用经典旧世实际存在的内容及明确标注的本作改编；不把新增现代系统悄悄记为复刻工作。
