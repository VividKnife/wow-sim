# 领域基础实施报告

本次实现位于 `packages/game-domain`。`GameService` 使用冻结的 Store/Transaction 接口；没有新增账号整档、历史格式兼容读写、迁移入口或第二套战斗规则。

## 实际接通

- 账号、稳定角色、伙伴档案、引用式队伍、个人钱包、物品位置与绑定、材料预留、活动、实例、合同、业务结算、账本、收据、outbox/inbox 与任务领取分别保存。
- `context.ts` 从角色规则字段与资产记录临时组装引擎上下文。命令执行后分解保存；账号不包含世界存档，角色不保存队伍/背包/钱包/活动/副本根对象。实例战斗对象保存在实例中，不回写到角色规则。
- 常规游戏命令经过原引擎 `act/advance`；招募产生独立角色与伙伴档案。装备转移校验所属账号/绑定，保留全局物品 ID。
- `activities.ts` 将采集、自动采集、制造转为持久活动。制造先验证原引擎配方规则，再原子移出材料和工具至预留记录；完成时仍通过原引擎制造逻辑结算。执行者、付款角色和收货角色分离；绑定产物限制收货人。主要专业最多两个。
- 活动拥有单独随机流与角色执行租约；冷却保存为绝对现实时间；召回有返回阶段，保留此前已结算收益，返回结束释放执行权。制造召回返还预留材料和工具。
- `instances.ts` 支持 5/10/20/40 席位、跨账号主动加入、每角色授权、递增 fencing epoch、独立模拟状态和序号。原死亡矿井与使用真实北郡怪物的第二个注册遭遇共用实例编排。40 席位只验证编排，不声称已制作 40 人团本。
- 佣兵使用注册模板、实例与付款人绑定的业务键扣费；更换 requestId 不重复扣款。佣兵不进入永久角色资产名册。
- 任务主角金钱/经验结算只调用一次 turnIn；同行合资格角色的装备通过独立领取键发放。再次提交、重新请求均不重复发放。
- 钱包和物品变动写账本。活动/命令/合同业务结算与 outbox 同事务写入；外部投递采用至少一次语义，inbox 记录消费者已确认事件。

## 接口

`createAccount`、`command` 返回与 `snapshot` 相同的 `{state,revision,account,roster,activities,instanceId,instance}`。这里是服务器内部返回类型；`state` 与活动内部随机状态必须由 HTTP 层显式 DTO 投影，不能直接发送给浏览器。

新增命令：`createCompanion`、`setParty`、`startActivity`、`recall`、`createInstance`、`joinInstance`、`startInstance`、`leaveInstance`、`hireMercenary`。既有 `craft/gatherResource/gatherAll/enterDungeon/leaveDungeon` 已接入相应持久流程。共享实例成员可配置自己的策略、恢复设置和宠物姿态，并使用已支持的法师手动战斗入口；其他访客命令明确拒绝。队长也不能控制其他账号角色。

`work(now,limit)` 返回 `{activities,instances,errors}`，扫描持久到期记录并主动推进。`acquireInstanceLease/advanceInstance` 暴露执行者恢复与 fencing 验证边界。

## 明确边界

- 当前活动和实例只运行注入的内容版本。版本不同将停止该项工作并返回错误，不以新版本静默修改旧活动；长期多版本内容加载仍需后续内容发布机制。
- 现有固定步长规则仍负责战斗。战斗每批最多 20,000 tick；旅行、采集按到期事件结算，安静空闲有快速推进路径。可复现 24 小时测量见最终交付报告。
- 订单失败保留预留与活动以便重试/召回；没有后台静默删除经济事实。
- 具有未完成制造收付款资产的角色暂不能加入实例，防止实例快照覆盖另一订单结算；这是一项明确的当前产品限制。
- outbox 回调可能在成功后、记录 inbox 前崩溃，外部消费者仍须按事件 ID 幂等；没有宣称跨外部系统的 exactly-once。
- 尚未声称完成新的大型团本内容、外部 PostgreSQL 压测或正式上线迁移。
