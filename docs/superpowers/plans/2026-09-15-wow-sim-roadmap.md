# wow-sim 首版实施路线

依据：[用户已确认的首版设计](../specs/2026-09-15-wow-sim-first-playable-design.md)。

本项目包含多个需要独立验收的子系统，按下面的依赖顺序分别制定和执行详细计划。首个计划只交付可运行的模拟基础库，不代表首版游戏已经完成。

当前进度：阶段 1 基础功能与 46 项测试已完成；阶段 2 已固定一份社区参考数据库归档并记录校验值，尚未完成目标版本核对及正式数据提取。阶段 3—7 尚未实现。

## 实施顺序

| 阶段 | 交付物 | 依赖 | 验收 |
|---|---|---|---|
| 1. 模拟基础 | 数值证据校验、可恢复随机数、事件时间线与旅行规则 | 无 | 数据缺证不能标记为已验证；分段推进与一次推进一致；状态可序列化恢复 |
| 2. 数据审计与提取 | 固定来源版本、1—20 级法师及队友数据、任务与副本实体清单 | 1 | 对比来源、阶段与实际行为，生成覆盖报告；不把社区实现自动认定为官方值 |
| 3. 战斗与角色成长 | 战斗事件、属性、命中伤害、法力、治疗、仇恨、策略、经验装备与任务 | 1、2 | 有来源的公式案例通过；随机概率检验；真实资源约束和战斗日志 |
| 4. 野外与存档 | 活动互斥、旅行、挂机、补给、离线结算和事务存档 | 1、3 | 重复请求不重复收益；分段和在线/离线结果等价；停止条件可靠 |
| 5. 小队与副本 | AI 招募成长、掉落分配、死亡矿井遭遇和断线暂停 | 3、4 | 五人职责有效；完成实际遭遇路线；重连不回滚、不重抽掉落 |
| 6. 手机网页 | 角色、世界、队伍、策略、战报及持久化服务入口 | 4、5 | 竖屏可操作、状态明确、前后台切换正确；完整旅程可实际游玩 |
| 7. 集成验证 | 正常存档的完整旅程与独立坐骑测试存档 | 2—6 | 数值覆盖公开、无测试赠送装备或经验加速补洞，坐骑原版门槛保留 |

## 文件与模块边界

- `packages/sim-core/`：纯模拟基础，浏览器与服务端都可导入，不依赖 UI、数据库或网络。
- `packages/game-data/`：数据包、转换清单、证据和覆盖报告；客户端表不覆盖未知服务器数据。
- `packages/game/`：角色、策略、战斗、活动、任务、背包和副本规则。
- `apps/web/`：手机网页和权威存档接口；后续使用 Sites 能力型项目，以满足持久存档需求。
- `docs/research/`：公式、数据来源差异、构建号和热修边界的研究记录。
- `docs/superpowers/plans/`：每个阶段的详细任务与实际执行状态。

## 技术选择

模拟核心使用无第三方运行时依赖的 JavaScript ESM，配合 Node 内置测试运行器。这样同一逻辑可以在命令行校验、服务端结算和网页中复用，后续接入前端框架不改变数值规则。

手机网页采用独立应用目录；服务端掌握存档与时间，事务存储保存事件游标、随机状态及活动。网页不能自行写入经验或掉落。此阶段不先创建空白网站或部署未完成的游戏。

## 数值可信度门槛

1. 先区分数值事实、参考实现与本作交互改编。
2. 游戏规则目标为 2019 首发，但客户端构建、服务器热修时间及具体数据快照需逐一固定。
3. 1.12 社区数据必须通过版本核对后才能进入目标包；未知值不得由公式或均值猜测后标成已验证。
4. 客户端不存在的掉落概率、服务端脚本和移动路径需要独立来源与实测证据。
5. 报告分别统计数据记录覆盖、机制实现覆盖和证据状态。
