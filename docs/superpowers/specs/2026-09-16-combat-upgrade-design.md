# 战斗表现、空间规则与小队策略升级

日期：2026-09-16

状态：用户已于 2026-09-16 授权直接实现；功能已落地，验证结果见同目录 `2026-09-16-combat-upgrade-validation.md`。

## 目标

让战斗中看见的移动、弹道、攻击动作与实际结算一致；用原版怪物图像提升辨识度；提供 DPS 统计、自动补 buff 和按怪物数量切换的职业策略。当前仍以单机角色及 AI 小队为运行方式，模拟接口为将来的多人房间留出边界。

## 实施前基线与缺口

- `apps/web/lib/game/combat.js` 已有 100ms 驱动下的近战接近、施法、减速、定身、仇恨与伤害记录。当前移动按每步 0.7 码硬编码，怪物构造没有接入原始数据的 `SpeedRun`、`SpeedWalk`。
- `apps/web/lib/combat-view.js` 用横向位置表达距离，纵向行只是排版；五人群怪战斗随单位数量变得很高。
- `apps/web/app/battle.tsx` 已有挥击、命中光圈、飘字、施法图标和短暂光迹；怪物仍用几何符号。现有光迹主要在伤害事件发生后播放。
- 玩家冰霜新星、魔爆术、烈焰风暴和暴风雪的部分结算遍历所有存活敌人，缺少与技能半径一致的筛选。
- `combat.damage` 按“角色名字 · 技能文本”累积；日志只保留最近 140 条，不能依靠日志重新计算完整战斗统计。战斗结束没有统一冻结时长的入口。
- 策略页只有主角优先级和吃喝阈值；手动 buff 存在，但没有自动维护。队友职业决策分散，法师队友使用默认规则。
- 当前 API 已有服务端时间、存档 revision、请求去重和页面控制权机制；这些是单人存档并发控制，不等于多人共享副本。
- 本地已导入怪物模型 ID、移动倍率、技能范围和半径资料。法术表同时包含玩家技能与同名 NPC 技能，不能仅按名称或 SpellLevel 判断角色是否可学。

## 方案选择

1. **推荐：统一空间与战斗事件，沿用现有运行链路。** 在现有确定性引擎中补充空间、事件、策略和统计模块，界面消费这些结果。功能范围满足本次要求，并保留现有任务、副本和存档流程。
2. **仅增强界面。** 改动较小，但无法解决全场 AOE、实际射程、个体移速和职业策略，不能完整满足需求。
3. **同步建设多人服务器。** 需要房间持久化、身份绑定、断线控制、共享战利品等额外产品规则。当前请求仅要求架构预留，不把这部分纳入此次实现。

## 1. 空间与移动

引入战场本地坐标 `{x, y}`，单位为码。战场布局、距离判定和范围特效使用同一套坐标。旧存档的标量 `position` 可迁移为 `{x: position, y: 0}`，不中断正在进行的战斗；新战斗使用分散的阵型和怪物出生点。

抽出 `combat-space.js`：负责距离、范围筛选、追击到射程边缘、有效移速和有限步长移动。每步位移为 `速度 × dt`，不会跨过目标或在射程边界反复抖动。

- 怪物基础移速取已导入模板的移动倍率，倍率单位与基准速度在实施时对照固定版本资料核验；缺失数据使用明确标记的模拟默认值。
- 减速统一由状态系统计算，重复同类减速取最强有效效果；定身使位移为零，持续时间届满恢复。定身本身不禁用仍在范围内的攻击或施法。
- 击晕、恐惧、变形继续各自遵守现有动作限制，并接入统一移动入口。
- 近战走到近战范围；法系走到合法施法距离后停下，不因一个高优先级技能暂时不可用就自动贴脸。
- 在施法开始和施法完成时分别检查该技能的目标合法性与射程；超距取消产生明确事件。引导技能按自身规则逐次判定。
- 范围技能区分以自身、目标或固定地面点为中心；地面效果不会随原目标移动。每个周期按当时位置重新筛选目标，并遵守技能目标上限。

首版使用二维平面距离与简单接近行为，不增加场景导航网格和地形遮挡判定；界面与说明不得宣称拥有尚未实现的视线判定。

## 2. 事件与未来多人边界

保持现有 `advance/act` 和服务端保存链路，拆出可复用的战斗规则模块。模拟不读取系统时间、不执行网络请求、不依赖 React，所有随机数继续由存档随机状态生成。

新增战斗标识和结构化事件：

```text
CombatEvent {
  encounterId, sequence, atMs, type,
  actorId, targetId?, spellId?,
  from?, to?, amount?, school?, critical?, periodic?
}
```

事件覆盖施法开始、完成、取消、弹道发射、命中/抵抗、近战挥击、伤害、治疗、控制变化和战斗结束。名字与中文说明只用于显示，不作为规则、效果或统计的键。

对具有弹道的法术，在权威状态保存待结算投射物及命中时间；飞行速度使用可核实的技能数据，缺失时标为表现适配值。伤害发生在命中结算，客户端动画不会触发伤害。目标提前死亡、退出战场等情况清理投射物，防止重复击杀和奖励。战斗结束统一处理剩余事件。

保存快照包含活动施法、投射物、控制状态、统计和事件序号；断线恢复不重播过期动画。客户端用 encounterId 与 sequence 去重，以快照纠正位置并插值显示。

命令适配层明确“操作者”和“受控战斗单位”的对应关系；当前由单人会话控制主角并为其余成员生成 AI 意图。战斗规则使用单位 ID，不依赖名字或某个唯一玩家对象。未来房间服务负责校验成员权限、排序命令并广播快照和事件；本轮不改变现有单人页面接管规则，也不声称已实现联机。

## 3. 战斗画面和怪物资源

用户已补充授权：如有需要，可以适当引入网页游戏或动画渲染引擎。渲染选型优先考虑 **PixiJS v8 + React**：PixiJS 负责战场、精灵、弹道及特效，React 负责策略、DPS、日志、菜单与可访问的单位详情。实际接入以生产构建和手机端验证通过为准；此处为基于现有代码边界的选型判断，并非已完成的性能测试。

战场采用自适应比例的二维视图，避免每增加一只怪就增加整行高度。名称、血条可做视觉避让，但单位锚点和弹道端点仍对应模拟位置。

### 渲染引擎取舍与接入边界

- **PixiJS 优先**：其定位为二维渲染引擎，具有 WebGL/WebGPU 渲染和独立帧循环，适合为已有模拟引擎添加精灵与特效表现层。当前项目已有规则、存档和副本生命周期，因此这一职责边界较匹配。
- **Phaser 备选**：提供场景、动画补间、输入和物理等游戏框架能力；若后续需求扩展为大量场景编辑与直接角色操控，再重新评估这套更完整的框架。此次不同时引入两个战场引擎。
- **SVG/CSS 简化视图**：保留为图形初始化失败时的降级显示，继续使用同一快照及坐标转换，确保能够查看战况和操作界面。降级由应用实现，不假设所选 PixiJS 版本会自动回退 Canvas。
- 引擎只在客户端进入战斗视图时动态加载；服务端渲染与模拟模块不能导入依赖浏览器对象的渲染代码。隐藏/关闭视图时暂停画面帧循环，卸载时移除监听和释放所属图形资源，正确处理异步初始化期间关闭窗口的情况。
- 定义独立 `BattleRenderer` 适配层，接收快照、结构化事件与画质设置；只向 UI 输出选中单位等交互，不修改权威战斗状态。PixiJS 的 Ticker 仅推进表现插值和特效，不累计伤害或驱动 AI。
- 暂定特效上限为 200 个轻量粒子，低画质降为 60；超出上限优先省略装饰粒子，保留弹道、作用范围和状态提示。限制渲染分辨率倍率，避免手机高像素密度放大开销；以五人群怪场景的实际帧耗时和内存表现调整预算，不预先承诺帧率。
- 纹理优先共用图集，窗口反复开启不能增加未释放的 ticker、纹理或监听器。减少动态效果模式仍保留信息明确的范围与命中提示。
- 引擎只提供图像和动画的播放能力；怪物真实外观仍依赖准确资源，有原版图标不等于拥有原版动作序列。

选型参考（2026-09-16 查阅）：[PixiJS 简介](https://pixijs.com/8.x/guides/getting-started/intro)、[PixiJS 帧循环](https://pixijs.com/8.x/guides/concepts/render-loop)、[Phaser 场景与系统](https://docs.phaser.io/phaser/concepts/scenes)。

- 火球、寒冰箭等表现为可移动的弹体和尾迹；瞬发、引导与周期伤害使用不同效果。
- 近战有面向目标的挥击、轻量动作位移和命中反馈；只有模拟坐标变化才改变实际距离。
- 冰霜新星显示以施法者为中心的扩散环；烈焰风暴、暴风雪显示固定地面范围；治疗、抵抗、暴击和控制各自有可辨识反馈。
- 单位详情显示当前目标距离、有效移速、减速比例、控制剩余时间和动作状态。选择单位时显示对应射程/范围提示。
- 怪物按 entry/model 映射本地资源。优先使用可核实的原版怪物头像或模型二维渲染；缺少准确对应资源时使用明确的原版类型图标回退，不把通用图标称为该怪物真实贴图。
- 新增资源清单记录来源、模型对应、文件路径和哈希，沿用仓库已有的来源记录习惯。初次覆盖当前可玩野外与死亡矿井怪物。
- 尊重减少动态效果设置，提供特效简化选项；手机端可折叠统计和事件面板。

## 4. DPS 统计面板

新增独立 `combat-metrics.js`，从权威伤害/治疗入口实时累计，避免用有长度上限的文字日志反推。

按单位 ID 和技能 ID 记录有效伤害、命中次数、暴击、周期伤害及技能明细；普攻使用明确的独立键。超出目标剩余生命的伤害不计入有效伤害。

面板提供：本场总伤害、DPS、伤害占比、职业色排名条；点击成员展开技能贡献。切换“当前/上一场”和“本次副本累计”；副本累计包含本次 runId 的所有战斗段，包括失败尝试，名称明确标为“本次副本全部战斗”。

本场 DPS = 有效伤害 / 实际模拟战斗秒数；零时长显示 0，避免无穷值。副本 DPS 的分母为战斗段时长之和，不含跑图和休息。战斗结束固定 endedAt，之后浏览战报不降低 DPS。全灭、捕获、召唤增援和其他结束路径都经过同一结算入口。

## 5. 自动补 buff

策略页面新增自动增益设置：总开关、逐项开关、目标范围（自身/符合条件的小队成员）、刷新提前量，默认提前 30 秒。

第一批覆盖可用且已学的长期增益：法师护甲与奥术智慧，以及接入技能白名单后的牧师真言术：韧。短期防护和战士消耗怒气的战斗增益由独立战斗策略处理，避免战前补 buff 阶段无法满足资源而卡住拉怪。

补 buff 复用技能结算，消耗真实资源、公共冷却和施法时间。只补缺失、即将到期或等级较低的效果，不重复覆盖更强增益；两个法师对同一队友使用确定的分工顺序，避免同一步重复补同一增益。

野外自动拉怪和副本已获指令的下一次遭遇，在开战前执行补给与 buff 准备阶段；法力不足时沿用现有补给规则并显示原因。死亡、复活、停止活动、缺少补给和已存在施法都有明确处理。默认长期 buff 不抢占战斗中的治疗、打断和保命行动。

## 6. 职业与群怪策略

策略页增加成员选择，主角和各 AI 队友各自保存策略。补充“范围内可攻击敌人数 ≥ N”条件，默认群攻阈值为 3，可调整。阈值是满足释放资格的条件，不绕过冷却、资源、已学技能、射程、姿态和目标上限。

计数针对该技能实际作用区域内的存活、可攻击敌人。提供默认开启的“避免打破变形等控场”设置；仅从计数中排除被控怪物还不够，实际范围会碰到需保护目标时也跳过这次 AOE。

- 坦克优先建立/维持仇恨和保护队友，再按数量使用合法群攻或多目标技能；遵守姿态、资源及下一次挥击技能的结算方式。通过目标选择与追击使近战怪自然靠近坦克，不瞬移聚怪。
- 法师支持魔爆术、烈焰风暴、暴风雪等实际已学技能的数量规则；自身范围技能必须到达合适距离才能释放。
- 盗贼仅开放实际已学或天赋解锁的技能；当前阶段没有合法群攻时继续单体输出，界面说明原因。
- 治疗继续优先救急、正常治疗和资源预留，在符合策略时才输出；不会为了达到 AOE 阈值而放弃需要治疗的队友。

新增可选的“等待坦克建立仇恨”条件，检测候选目标当前目标/仇恨状态。它影响输出启动时机，不保证后续永不 OT。

## 7. 兼容性与文件边界

保留现有数据与 API，新增字段通过版本迁移补齐；旧规则继续可用，旧快照的标量位置有明确转换。旧战报没有可靠时长/技能 ID 时显示旧统计或不可用，不伪造精确 DPS。

计划新增空间、事件、统计和策略辅助模块；在 `combat.js`、`companion-combat.js`、`combat-auras.js`、`engine.js`、`character.js`、`party.js` 与副本准备流程中接入。UI 更新 `battle.tsx`、`battle.css`、`combat-view.js`、`strategy.tsx`，增加独立战场渲染适配器；如接入 PixiJS，同步更新应用依赖和锁文件，资源另附清单。

当前工作区已有大量未提交实现。只在相关文件进行增量修改，不重置、不覆盖现有工作；本草案独立保存，不将整个工作区提交。

## 8. 实施顺序与验收

1. 空间规则及迁移：验证不同移速、减速到期、定身仍能攻击近处目标、超距不能攻击、追击不越界和 AOE 边界。
2. 战斗事件与投射物：验证开始/命中时间、死亡目标清理、存档恢复、重复事件去重和不同时间分段推进的一致性。
3. 统计：验证多目标和 DOT 累计、重名角色分开统计、日志截断不丢数据、结束时长冻结、全灭及副本累计。
4. 自动 buff 与职业策略：验证资源和公共冷却、停止/恢复、同名增益不重复、未学/不合法技能跳过、N-1/N 阈值、范围与控场保护、治疗优先。
5. 视觉与资源：在真实引擎测试夹具中检查野外单怪、五人群怪、不同法术、控制状态和 DPS 面板，验证原版图像与回退均可加载。
6. 回归：运行现有 Node 测试、语法/类型检查与生产构建；浏览器核验桌面和 390px 手机布局、减少动态效果与断线恢复。接入引擎后另核验客户端动态加载、反复开关窗口资源释放、图形初始化失败降级，以及五人群怪的帧耗时与内存表现。

实施时将上述边界写成有行为意义的回归测试。新增规则可能改变副本胜率，需要复跑现有副本基准并报告变化，不以任意加强数值来掩盖距离或策略错误。

## 已实施范围与边界

已实施二维空间与真实范围结算、事件驱动特效、原版怪物类型图标、DPS 面板、自动长期 buff、按成员配置群怪策略，以及保持单人运行的多人架构接口准备。兼容旧存档采用数值 `position` 加 `positionY`，未替换为对象字段。尚未实现多人网络房间；怪物使用原版种类/类型图标，不宣称为每个 NPC 的专属贴图或动画序列。
