# AI 队友：副本佣兵与长期伙伴设计提案

日期：2026-09-16，第二次修订。状态：两类队友、每角色任务装备、角色双专业、个人专业收益和实时外派采集已由用户提出；其他具体成长/计费/上限规则为建议方案。尚未实施。

## 1. 已明确的产品方向

- 副本佣兵：当前等级毕业配置，付金币雇佣，每个新副本重新雇佣，不参与装备需求，掉落由玩家获得/分配。
- 长期伙伴：免费招募、持续成长，可分配副本装备；避免让玩家重复管理多个完整小号。
- 任务装备：每位符合任务条件的角色有自己的一份奖励，不能让整个小队只分同一件任务装备。
- 角色专业：主角和每位长期伙伴分别指定两项主要专业；不能以共用页面代替角色专业归属。
- 专业收益：采集、制造的执行者及收益归属明确到角色，专业带来的角色专属收益也归该角色。
- 外派采集：未参加副本的长期伙伴可以按实际时间外派自动采集；制造在一个页面统一操作。

这项新方向取代旧首版设计的单一免费队友限制，也取代上一版提案的“全队只领一份任务装备”“共享专业档案”和主角不限主要专业数量建议。等级与具体专业成长速度仍属建议，不直接覆盖运行时规则。

## 2. 推荐定位

| 项目 | 副本佣兵 | 长期伙伴 |
|---|---|---|
| 用途 | 花金币补齐实力、过卡点、刷目标装备 | 常驻冒险与队伍养成 |
| 招募 | 按本按人报价、确认合同 | 免费，永久保留身份 |
| 等级 | 合同创建时取主角等级，上限 60；副本中不升档 | 跟随主角等级，脱战/安全点同步，不另攒经验 |
| 装备 | 对应等级、阶段、职业职责的毕业模板 | 独立装备；每角色任务装备、掉落/制造/购买；低配保障 |
| 策略 | 成熟默认策略，可配置任务分工 | 默认天赋与策略，可自定义和保存 |
| 掉落 | 不掷点、不需求、不额外生成奖励 | 玩家主动分配合用装备；默认不自动抢装 |
| 专业 | 无私人专业收益，也不可外派采集 | 每人双专业、独立执行与收益归属，共用操作页面 |
| 费用 | 显示总价，合同内补给与维护包含在报价 | 无工资；统一预算面板管理个人资产与公共补给 |
| 存续 | 绑定一次实例运行，通关/重置/主动终止结束 | 未出战也保留，换人不删除 |

五人队可混搭，例如主角 + 两个长期伙伴 + 一个佣兵 + 一位朋友。容量和职责遵守实例规则。

## 3. 副本佣兵规则

### 装备模板

1—59 级按等级、开放阶段、职业和职责生成当前可穿戴的任务/副本毕业配置。先按等级段建立模板，再根据关键武器、技能与等级限制细化；不需要每次招募实时求解所有装备组合。

“毕业”不以平均装等排序：武器伤害/速度、法强、治疗、命中、防御、抗性、套装和触发可能比装等重要。模板必须能说明来源和职责。若用属性预算简化，UI 应写“毕业强度模板”，不能展示并未实际实现的套装/触发并声称精确毕业。

60 级建议使用当前开放阶段的职责毕业模板，不跨阶段拿后续团本装备。雇佣阶段毕业队伍会降低开荒难度，这是付费打手模式的产品取舍；不能同时承诺原汁原味的弱装开荒。仍要遵守首领机制、控制、资源和失败条件，不直接保证通关。

模板在合同签订时冻结。主角升级、切装、内容数据更新不应在同一次战斗内暗中提高佣兵属性。需要换模板在下一次合同生效。

佣兵装备和补给标记为合约资产：不能取走、交易、出售、分解或移交长期伙伴。战斗中正常消耗/冷却，但不从玩家背包暗扣报价外费用。

### 计费与合同

- 进入前显示每名佣兵价格、装备强度、职责和合计，一次确认。价格由副本档位、模板强度与人数确定；不先写死缺乏经济测量的金币值。
- 首次开战时扣费并激活，扣费与合同状态必须原子提交；开战前取消释放预留金币。
- 同一 `instanceRunId` 的团灭、复活、休整、离开补给、断线和重新进入不重复收费。
- 通关、主动重置为新实例、主动结束合同才终止。重新开本重新付费，重新打开网页不算重新开本。
- 技术故障恢复优先保留合同；无法恢复时按持久结算记录补偿。不能通过刷新无限领退款或重抽掉落。
- 佣兵不提供额外个人金币、任务奖励或掉落份数。收费换取战斗服务，不是购买额外 loot roll。
- 普通副本按次签约。未来团本建议按同一个锁定实例签约，允许跨日续打；不能每次重连收一遍费用。

价格需要基于对应等级真实金币来源、维修补给和正常副本净收益测量。目标是偶尔雇佣能负担、长期依赖有明显成本、培养伙伴后能节省金币；不能简单收费高于掉落卖店价，因为刷装备本身就是合理目标，也不能制造无限稳定增金循环。

### 掉落语义

“装备都是你的”适用于玩家与 AI 的个人冒险：玩家掌握单份战利品的分配，不意味着每名 AI 额外掉一份，装备仍需满足职业和等级要求，同账号主角与 NPC 伙伴间可交换绑定装备。可按规则留给主角、分配给在场长期伙伴或处理掉落。

有其他真人时，真人保持正常资格与约定分配；雇佣者不能因为支付佣金获得全队独占掉落。佣兵始终放弃需求。分配前允许对比角色收益，同账号主角与 NPC 伙伴可反复交换同一件绑定装备，物品实例始终只有一份；真人间交易规则另行设计。

## 4. 长期伙伴成长：推荐规则

### 等级和技能跟随，装备留下养成空间

- 当前等级自动跟随所属主角；替补也跟随。无需重练或给低级伙伴额外刷经验。
- 等级同步本身不发奖励；每角色任务装备通过独立的任务奖励资格与领取记录发放，不能因升级或刷新重复领取。
- 战斗中不瞬间升级回血；在安全结算点调整等级和上限，保留合理资源状态，不能切队友当免费治疗。
- 常规训练技能与武器/护甲能力按等级自动配置；天赋点使用职业职责模板，提供一键重置为推荐方案和高级自定义。
- 需要特殊任务取得的能力使用明确的伙伴解锁表，按已完成的冒险里程碑解锁；不要求四名伙伴重复跑同一条链，也不自动给主角补发职业奖励。
- 等级同步只是伙伴便捷规则。主角经验仍按明确的队伍结算规则计算，不因“不记伙伴经验”而自动把五人经验全加给主角。

长期伙伴的主要成长来自装备、配装、天赋与队伍组合。首版不增加忠诚度、饥饿、每日好感任务、随机离队或额外经验条。

### 装备：低配保障、真实提升

新招伙伴有符合等级/职责的基础配置，保证能参与同级普通冒险；明显低于佣兵毕业模板。避免新招 50 级治疗仍拿 1 级武器，却要求先养很久才能使用。

建议设置“基础装备保障”：按等级段更新不可交易的低档制式装备，填空槽或提供落后装备的替换建议。优质真实装备不自动销毁/覆盖；保障装不能出售、分解或用于任务，反复招募不产出资产。

每角色任务装备保证练级期间的持续提升，副本装备、制造装备与购买装备提供进一步成长。保留角色独立穿戴和绑定；共用小队储物界面，无需额外打开四套背包。

掉落提示“主角提升 / 伙伴 A 提升 / 伙伴 B 提升”，可一键分配。可选自动装备仅作用于未锁定、明确允许的装备；涉及稀有、套装和主角需求时先保留。属性评分解释职责和关键属性，不能只比装等。

### 任务：共用操作，每角色获得自己的装备

- 主角维护一份冒险任务操作入口，不要求分别接交四次。每位符合条件的长期伙伴拥有个人完成/奖励领取记录。
- 完成带装备奖励的任务时，主角与符合条件的伙伴各自从该任务的合法奖励选项中选择一件；若任务含固定装备奖励，也按其规则分别处理。不是每人获得全部备选奖励，也不按职业虚构任务中不存在的物品。
- 可根据伙伴职责自动推荐或自动选择，交任务时一个页面展示全队所得，避免五次点击。没有合用选项时如实显示，不自动换成等价毕业装。
- 推荐已招募伙伴共享普通世界任务里程碑，外派/替补也能按条件获得个人装备，避免为了领奖频繁召回。职业、阵营、等级和前置条件仍需逐人校验；职业专属任务不全队通发。
- 个人奖励记录以稳定角色 ID、任务 ID 和完成轮次去重；刷新、换阵容、解雇重招都不能重复领取。新伙伴不批量补发全部历史任务物品，使用起始保障装备追赶；这是建议的追赶规则。
- 为让额外装备服务于伙伴成长，建议伙伴份额的任务装备绑定本人，不转主角、不出售、不分解；换下可保留或销毁。主角原有奖励仍遵循原规则。这是建议的经济边界，不代表原版物品规则。
- 本次确定的是每角色任务装备；不据此自动把任务金币、稀有消耗品或剧情物品也乘以人数。建议金币和通用材料仍按冒险结算一次；如需个人任务金币，应另做经济测算。
- 副本首领/怪物掉落仍按一次遭遇正常生成一个战利品池，不能套用每人一份任务装备的规则。

### 资产、金币与补给：统一界面，保留归属

伙伴没有工资或强制分红，但有自己的资产归属和收益记录。采集产物归采集者，制造产物默认归制造者，出售后的专业收入记在该角色名下；不能只在展示中写名字，入库后就丢掉归属。

建议提供“总仓储 + 按角色筛选”和统一钱包总览，后台保留个人物品与余额、公共资金及划转账本。可配置非绑定材料自动共享、个人收入自动汇入公共预算，减少手动转账；共享不复制物品，同账号普通绑定装备可跨角色分配，专业专属物品继续遵守使用资格。

制造前显示材料提供者、执行者、费用支付者和产物接收者。非绑定材料可按共享授权从全队取用；不能因为页面共用而绕过绑定、持有数量或预算限制。

提供统一补给/维护预算和可见扣费。未活动的伙伴不消耗补给；外派中的伙伴消耗其真实活动所需物资，不因退出网页产生额外养护账单。

## 5. 生活专业：每人双专业、个人收益、共用工坊

### 角色专业与成长

- 主角、每名长期伙伴各有两项主要专业，保存各自的技能值、配方解锁、专精和冷却；佣兵不能提供专业产出。
- 建议烹饪、急救、钓鱼作为生活技能另列，不占这两个主要专业位；这是对“双专业”范围的建议解释。
- 建议专业熟练度归本人，按本人实际采集/制造自动增长，不再自动复制主角或全队最高专业等级。操作集中在一个页面，不需要切到伙伴重新练角色等级或接普通任务。
- 同样学炼金的两个角色可以处于不同熟练度；只给执行制造的角色涨技能。主角角色等级提高，不直接把所有专业填满；专业进阶仍检查允许条件，可提供一键办理训练。
- 保留按技能值自动解锁常规配方的便捷方向，但逐角色检查阶段、专精、工具、材料、地点和特殊资格；具体配方追赶方式作为后续参数，不声称当前已实现。
- 专精与个人制造冷却归该角色，不因换出队伍/改专业/重招而清空；同一角色互斥专精仍互斥。不同已培养角色的合法专精和冷却带来的额外产能是个人专业收益，须纳入经济预算，不静默改成全队同一个冷却。
- 角色专业专属装备、物品使用资格、特殊制作权限等只作用于本人；只有所选版本实际存在的收益或明确标注的改编才加入，不能默认套用其他版本的专业被动属性奖励。

### 共用制造页面

工坊提供统一搜索、配方展示和订单队列，每张订单必须绑定执行角色。例如：

```text
艾琳（炼金 160）：制造治疗药水 × 20
加瑞克（锻造 120）：制造装备 × 1

每单显示：执行者 / 材料来源 / 支付账户 / 产物归属 / 所需时间
```

可自动推荐当前合格且空闲的角色，但下单后执行者固定。产物默认归制造者；可交易产物允许预设交给主角/伙伴，专属或绑定产物仍归合法角色。技能提升、制造冷却和专业专属效果均记在执行者本人。

首版建议同一角色一次只执行一种活动：随队战斗、旅行、采集、制造。独立伙伴可以并行执行各自订单，不再用全队单一队列人为取消个人专业产能。

### 按实际时间外派采集

玩家选择伙伴、已解锁目的地/路线、采集专业、目标资源与时长或数量，然后下达派遣。需要具备对应专业/熟练度、等级和工具；不能给不会采矿的角色下采矿任务。

活动过程：`前往 → 寻找/采集 → 继续或停止 → 返回 → 入库`。途中、等待刷新、采集动作、背包容量与返回都占用实际时间。UI 显示预计收益区间而非保证固定产量，产量来自实际资源和成功结果。

时间由服务端起止时间与已结算游标推进；离线照常，分批结算与一次追赶一致。多开网页、修改本机时间或重复收取不增加产量。任务订单版本、路线、种子及收益记录持久化。

同一资源刷新实例只能采收一次；多人/多伙伴走相同路线时必须处理资源争用，不为每个页面复制矿点。外派是实际独立活动，完成后产物、技能增长、专业收入全部归执行者。

剥皮外派要包含可剥皮目标的实际狩猎与消耗，不能没有尸体就定时生成皮革。是否追加其狩猎普通掉落应在活动规则中明确；不把伙伴外派击杀悄悄计入主角经验和任务目标。

停止条件包括任务时长/数量达到、背包满、工具/补给不足、无可用资源或不满足区域安全条件。无资源时显示等待/停止原因，不补发固定收益。遇到危险按可配置撤退规则处理，不做离线无限死亡复活。

### 与组队的互斥

- 外派角色不同时参加副本或制造；正在打本的角色不能被派出去采集。
- 召回停止安排新的采集动作，已完成收益保留；按返回路程回到可加入队伍的地点，界面显示剩余时间。
- 进本前选择“等待召回”或“换其他伙伴/佣兵”，不能同一角色一边打本一边持续产出。
- 未进入副本的其他长期伙伴可以继续外派，主角进本不暂停整个名册；这是建议的并行规则。
- 为避免免费无限招人等于无限产能，建议首版设四个外派/工坊后台工作位，账号共享；名册可更大，角色出战另算。不按职业重复购买限制收益，而按实际工作位、资源和时间控制。四个是待平衡参数，不是用户已定值。
- 取消/换人只结束当前订单，不刷新资源、个人制造冷却或个人领奖资格。伙伴身份和记录持久保存，不能通过重招生成全新经济身份。

## 6. 名册、日常操作与差异化

推荐首版提供四个出战位、若干永久伙伴名册位；名册上限和解锁方式属于后续 UI/存档设计参数，不预先制造付费门槛。允许保留多个职业以应对队伍需要，但不强迫一次培养九职业。

玩家日常只做：

1. 选择此次队伍：长期伙伴、临时佣兵或真人。
2. 为主角和伙伴设置各自双专业、职责、默认策略和补给预算。
3. 在统一页面下达采集/制造订单，查看个人收益和全队物资。
4. 任务装备自动逐人推荐，副本好装备决定给谁；其余技能/等级/普通任务操作自动处理。

佣兵优势是立即强、无需投入装备、无需求；长期伙伴优势是免费常驻、装备投资长期有效、可自定义与陪伴感。长期伙伴成长后应有机会接近同阶段佣兵，不设计佣兵专属隐藏倍率长期压制玩家养成。

佣兵也应对失败可解释：装备毕业不等于免疫控制、自动完成所有首领机制。界面说明职责和策略质量，佣兵与长期伙伴遵守同一套战斗规则。

## 7. 与已有源码的衔接

已检查的当前实现：`apps/web/lib/game/party.js` 只有一种招募，候选按主角等级和装备预算生成，四类固定角色；配发装备使用 `issued/bound/ownerId`。候选物品池还限制 `ItemLevel<=25`，不适用于直接宣称 1—60 毕业佣兵。

该新设计需要扩展名册和类型，不应只在 recruit 上加一次扣金币：

- `companionKind` 区分 permanent/mercenary，永久角色与当前出战席位分离。
- 佣兵保存 templateVersion、报价、payer、instanceRunId 与合同状态；重入同本幂等。
- 永久伙伴等级同步与战斗资源变化放在安全结算入口，不能按页面刷新触发。
- 专业、冷却、物品和收益记录绑定稳定角色 ID；页面聚合不合并专业档案。真人 A/B 组队不共享专业等级、钱包或库存。
- 每角色任务奖励单独保存资格/领取凭据；一份任务操作可产生多个合法角色奖励，但每份只能发一次。个人成长用装备的转移/变现限制独立于主角原奖励规则。
- 外派订单保存执行者、目的地、专业、开始/结算时间、状态、资源与归属；个人活动租约保证采集/制造/战斗不重叠。共享材料划转需要账本和原子扣减。
- 战利品分配使用 item instance 唯一归属；佣兵合约资产不可转移，伙伴普通绑定战利品可在同账号主角与 NPC 伙伴间交换。
- 后续联机实例控制权、经济账本和阶段筛选采用上线规划中的统一接口。

## 8. 建议开发顺序

这仍是设计提案，以下为后续工作包顺序，不是已经启动的实施计划。

1. 建立两类队友与永久名册，保留原有战斗/策略接口。
2. 永久伙伴等级/技能同步、基础装备保障、每角色任务装备与个人领奖凭据。
3. 佣兵模板、单次合同、报价扣费、断线/全灭/重入/结束规则。
4. 个人冒险和真人队伍的装备分配与领取权限。
5. 主角/伙伴双专业、个人熟练度/专精/冷却、资产归属与共用工坊订单。
6. 外派采集、实际时间与离线结算、召回及副本互斥、后台工作位。
7. 正常成长与经济对照：长期伙伴、混合队伍、全佣兵；另测多人外派材料供给与物价影响。

最少验收：新招/替补等级同步；切换不回血/不复制装备；每个合法角色收到一份任务装备且重复领取不增发；非法职业/阵营不得领奖；主角与伙伴各自双专业；只有执行者获得技能/产物/专属收益；个人冷却不被切换重置；一个资源刷新实例只采收一次；离线/分批/重复请求结果一致；采集者不能同时打本；召回保留已完成收益；共享材料不双花；佣兵重连不重收费、新实例重新收费；合约装备不能变现；真人组队不丢分配权；高阶段模板不可提前使用。

## 9. 本次修订的确认与建议边界

用户明确：任务装备按角色发放；主角/伙伴各自双专业；专业收益归执行角色；未打本伙伴可按实际时间自动采集；制造共用页面但指定执行者。

仍为建议：等级自动跟随、普通世界任务共享资格、伙伴任务装备不可变现、个人专业独立自动成长、三项生活技能不占主要专业位、收益自动归集配置、四个后台工作位、召回旅行规则，以及佣兵具体报价。不能把这些建议写成已经由用户逐条确认或已实现的规则。

以上便捷行为和佣兵模板都应登记为 wow-sim 的交互改编，不标记为原版规则复刻。
