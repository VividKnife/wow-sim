# GM 管理后台

## 入口与初始化

访问游戏域名下的 `/admin`（也支持 `/admin/`）。使用现有 `APP_ORIGIN`、`DATABASE_URL` 和 API 网关配置，无需额外端口或环境变量。游戏服务启动时自动创建管理相关表。

尚无管理员时显示注册表单。第一个**注册成功**的用户成为唯一管理员，并自动登录；之后注册 API 和界面均关闭，不支持自助增加管理员。数据库 singleton 主键保证多个进程同时注册也只会产生一个管理员。只是打开页面不保留注册资格。上线后应由服主首先完成注册。

管理员账号独立于玩家账号。用户名为 3–32 位字母、数字、下划线或短横线，不区分大小写；密码为 12–128 个字符。后台会话有效期为 8 小时。

## 功能

| 模块 | 已实现功能 |
| --- | --- |
| 运营概览 | 注册玩家、存档、角色、近一分钟活跃存档、进行中活动/副本、封禁数量 |
| 玩家管理 | 用户名或 ID 搜索、封禁、解封、强制退出 |
| 存档与角色 | 按玩家、角色名或存档 ID 搜索，查看角色状态及钱包余额（铜币） |
| 活动巡检 | 查看活动类型、状态、所属存档及下次调度时间，支持搜索 |
| 礼包与 Buff | 创建/编辑礼包，发给全服或指定玩家，配置/发布/撤销全图增益 |
| 操作审计 | 查看首次注册、玩家管理、礼包配置/发放及 Buff 操作的目标、管理员、时间、原因 |

列表每页 25 条，支持前后翻页。数据通过刷新按钮重新获取，不自动轮询。角色详情是只读诊断数据。奖励通过礼包发放，不提供任意 JSON 写入或副本强制结算。

封禁会撤销当前所有游戏会话并阻止后续登录。解封后玩家需重新登录。强制退出只撤销现有会话，玩家可以重新登录。已订阅的 WebSocket 在下一次服务端推送轮询时检查会话并关闭连接。客户端断网期间的本地画面可能继续运行，但不能使用失效会话上传状态。

## 数据与安全

- `gm_admin`：唯一管理员，scrypt 加盐密码哈希。
- `gm_sessions`：只保存 token 哈希；`wow_admin` Cookie 使用 HttpOnly、SameSite=Strict、Path=/api/admin，生产环境额外启用 Secure。
- `gm_audit`：管理员操作审计，前端不提供删除或修改入口。
- `web_user_blocks`：被封禁的玩家及原因，游戏登录与会话校验共同检查。
- 所有后台查询和操作均校验独立管理员会话；写操作沿用 APP_ORIGIN 来源检查；登录和注册使用数据库限流。
- 封禁、解封、强制退出和审计记录在同一 SQL 语句中原子提交；操作必须填写 1–500 字原因。
- 管理服务未注入时 API 返回 503，不回退到玩家鉴权。

## 礼包配置与领取

在「礼包与 Buff」选择礼包配置，可搜索物品名称或 ID，添加最多 20 种物品、每种 1–1000 件，并设置金币、名称和玩家可见说明。金币最多四位小数，1 金 = 10000 铜。礼包至少包含物品或金币；模板可再次编辑，已投递的内容保持发放时的快照。

发放范围为全服或指定玩家账号。一次发放给目标**已有存档**各投递一份，不补发给此后新建的存档。每次新的发放都会产生新礼包；网络重试使用相同请求编号，不会重复投递。填写原因后可一键发放，并在确认窗口核对目标。

玩家在经典/网页两种界面都有「奖励」入口和待领取数量，约每 15 秒检查新礼包，回到页面时也会更新。打开后查看物品、金币、说明并领取到当前角色；整包物品、金币、领取状态及资产流水在同一事务中提交。

背包校验考虑堆叠及唯一物品限制。空间不够时显示“背包空间不足，请先清理背包再领取”，整包保留且金币也不提前入账。窗口提供打开背包入口；清理后可以重试。重复或并发领取只能入账一次；不能领取其他存档的礼包。跟随队伍或进入副本仍可领取，本地模拟会先保存进度再提交奖励，晚到的旧检查点无法覆盖奖励。

## 全图与定向 Buff

Buff 可配置名称、玩家说明、1–43200 分钟时长，以及以下效果：

- 经验倍率 1–10，移动速度倍率 1–3，与原有服务器倍率相乘。
- 生命上限、法力上限、护甲各增加 0–100000。
- 近战攻击强度、远程攻击强度、法术强度、治疗强度各增加 0–10000。

至少配置一种非默认加成。不同 Buff 倍率相乘、属性相加；单个玩家最多同时获得 32 个 GM Buff，GM 经验总倍率上限 1000、移动总倍率上限 10。没有法力条的角色不会因法力上限加成获得法力条。生命/法力上限提升不直接补满当前资源。

全服 Buff 覆盖所有地图、阵营和角色；指定玩家 Buff 覆盖该账号的角色。有效期内新建的角色也会继承。持续时间按真实时间计算，离线同样计时；后台可填写原因后提前撤销。玩家 Buff 栏显示名称、说明与剩余时间，属性和经验/移动计算使用相同效果。

在线本地模拟通常在下次检查点同步（约 10 秒）接收新增或撤销的 Buff；正常检查点仍仅返回资产 ID，只有增益发生变化时追加效果更新，不重启战斗。服务器保存上次授权的增益用于验证，客户端不能自行添加或修改。云端活动清除旧的预计算战斗计划，按新配置推进。历史有效时间窗保留用于离线结算，避免在 Buff 发布前的战斗中追溯获得加成。

新增持久化表：`gm_templates`（礼包模板）、`gm_deliveries`（投递和领取状态）、`gm_buffs`（生效时间窗）、`gm_operations`（幂等请求与审计）。管理员登录表与玩家账号不变；重启服务自动建表。发放和审计原子提交，审计写入失败时不会留下部分发放。
