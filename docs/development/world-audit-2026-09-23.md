# 全游戏内容与运行时审计 · 2026-09-23

> 以下保留首次审计的失败基线。后续修复与最新验证结果见 [世界内容修复记录](world-audit-fixes-2026-09-23.md)，不要把本报告中的旧失败数量当作当前状态。

结论：当前世界骨架和大部分既有回归正常，但不能视为完整可通关。最优先的问题是任务目标可执行性、任务交付端点、任务条件解释与地图归类；其次是职业战斗回归及副本专属事件。仅“已导入任务”和“地图连通”不足以证明内容完成。

本次检查针对当前工作区（含开始审计前已有的大量未提交变更）。没有修改游戏规则、数据、用户存档或既有测试；新增两个可重复执行的审计脚本及本报告。没有对照在线原版资料重新考据，范围以仓库的 1—60/P1 定义为准。

## 已确认问题（按优先级）

### P1 · 可接任务的目标被怪物筛选器排除

`catalog.js:205` 的 `monsterIdsAt` 排除 `CreatureType=10`、所有带 NpcFlags 的生物，并以地点等级上限限制目标。`quests.js:48` 仅在目标完全没有地点时生成替代场景。因此“有地点但不能战斗”的目标不会得到补救。

实际用 `act(accept)` 接取，随后查看任务目标、替代场景并尝试 `act(hunt)`：

| 任务 | 复现 |
| --- | --- |
| 1147 疯狂的虫群 | 三种异种虫目标均为 CreatureType 10；狩猎被拒绝，场景为空 |
| 4145 拉瑞安和穆尔金 | 四种血瓣花目标均被同一类型筛选排除 |
| 505 辛迪加刺客 | 窃贼 2241 归到等级上限 30 的塔伦米尔，33 级目标超出 max+2 |

同类扫描发现 **71 个目标引用，涉及 46 个任务**。这是候选集合，包含节日/后续内容；上述样例已确认。任务 529 的铁匠和见习铁匠因 NpcFlags 被过滤，也是需要逐项处理的目标。

修复方向：把“世界可攻击对象”“服务 NPC”“任务交互代理”分别建模，任务目标对真实可执行动作做校验。不要简单移除全部友好 NPC 过滤；联盟与部落仍应遵守互不敌对规则。

### P1 · 最近距离映射把区域目标送进错误区域

`catalog.js:170–183` 的 `nearestNode` 只按大陆和距离选节点，没有区域边界约束。任务 **3063 对鹰身人的复仇**在莫沙彻营地可接，但四种北泉鹰身人都被分配到凄凉之地 `gelkis`（吉尔吉斯村，30—40 级），又被等级过滤移除。实际接取后没有场景，前往指引地点也不能狩猎。

修复方向：补足区域地点锚点，使用区域边界/源区域约束并保留必要的明确放置。地图连通测试不会发现这种“路径存在但目的地错误”的问题。

### P1 · 交互型任务目标被当作击杀，缺少物品使用动作

**5097 标记哨塔**正常接取后会发放 12815，但四座哨塔显示为击杀目标。哨塔有地点，所以不会触发替代场景；又不可狩猎。`quest-tools.js` 仅定义三个早期法师工具，没有此任务的使用动作。5098 有同类结构。

修复方向：任务需求必须显式区分击杀、标记、对话、物件使用和召唤，不应依赖目标 ID 正负值推导全部行为。

### P1 · 副本任务缺交付对象，完成目标后仍无法交付

**2201 寻找宝石**可在奥达曼接取。探针补齐三颗宝石后 `questProgress.complete=true`，但 `endLocations=[]`，交付物件 **112877** 的模板不存在。后续 **2204 修复项链**也以该物件为起点。

还发现科尔戈的黄金的物件 142194，以及拭目以待/石头卫士等使用的 142343 缺模板。部分副本内剧情 NPC（如 7046 塞雷布拉斯节杖的端点）没有可定位实例。全量扫描：55 个任务无可定位起点、50 个无可定位终点、11 个端点模板引用缺失、20 个场景引用无地点。各集合重叠，不能相加为坏任务数量，也包含节日和范围外内容。

### P1 · 急救专业键名不一致，满足条件仍不能接任务

专业系统存储 `professions.firstaid`，`quests.js:9` 将技能 129 映射为 `firstAid`。225 急救、60 级的人类仍无法接 **6625 Alliance Trauma**。同字段还影响 6622、6623、6624。

### P1 · 任务条件解释器不完整

`quests.js:11` 的 `meetsCondition` 对未实现类型返回 false，且未处理源条件 flags。**1641 The Tome of Divinity**的类型 23 背包/银行条件使满足等级、种族、职业的新圣骑士无法接取；1645 有同类条件。**7703 戈多克食人魔的事务**依赖类型 1 光环条件，当前解释器同样不支持。

扫描共 **74 个任务含未实现条件类型**。它们不一定全表现为“无法接取”：例如 NOT 包裹未知条件会变成 true，可能提前开放任务。5122/5125 的实例条件正好采用这种结构。修复须覆盖逻辑组合、flags 与实例状态，不能把未知条件统一放行。

### P1 · 猎人驯服真实回归

现有三个驯服/宠物技能获取测试失败，独立复跑仍失败。用 60 级兽人猎人、已学驯服、北郡幼狼复现：调用施法时成功建立 20 秒引导，推进 **100 ms** 后引导变成 null，日志为“引导中止：目标超出射程”。

`combat.js:55–66` 依据最长策略射程生成野外敌人；`beginHunterTaming` 在创建战斗后直接开始驯服，没有保证目标在驯服射程内。`combat.js:329` 下一 tick 即进行射程检查。应让公共施法入口和新开战的出生距离遵守该动作的射程约束。

### P2 · P1 范围排除只看 ZoneOrSort，后续阶段链仍会开放

`quests.js:10–12` 用少数区域 ID 排除后续内容。任务 **9121/9122/9123 恐怖之城，纳克萨玛斯**归属东瘟疫之地 139，因此不会被排除，且后续 **9033** 根本未导入。60 级、银色黎明声望 10,000 的角色可通过 9121 的接取条件。

修复方向：对任务及依赖链维护显式范围与可玩状态，区分 P1、后续阶段、节日、已废弃和暂不支持；不要仅依赖任务所在区域。浏览器世界页也能看到节日/马戏团人物和任务，需要明确是否希望常驻。

## 地点、NPC、主城与副本覆盖结论

- 所有 309 地点可从北郡经现有路网到达，坐标有限；道路端点及飞行点未发现缺失/孤立引用。
- 现有测试验证了所有合法种族职业的出生点、当地任务和低级怪物；种族背景保留。
- 六大主城分别以联盟和部落角色验证银行、炉石绑定、训练入口、飞行解锁与飞行，没有发现阵营阻断。商店规则也没有阵营过滤。
- 主城训练与专业服务在若干地点采用通用入口/代表 NPC；通过服务测试不代表每个原版 NPC 已逐一恢复。
- 28 地下城分区均有入口、遭遇、可达地图节点和有效怪物模板；现有测试验证进度保存与恢复，地图/首领资料重点复跑通过。
- 熔火之心 25 段路线的真实战斗测试通过；奥妮克希亚三阶段、真实战斗通关、奖励幂等和服务端实例保存测试通过。这不证明全部普通副本已按自然等级从头到尾实战通关。
- **明确尚未完成**：黑石深渊酒吧/竞技场事件、厄运贡品流程、通灵传送房间等；团本门任务未强制入场。仓库 `world-1-60-p1.md` 已说明这些限制，`interactDungeon` 当前专属分支只有死亡矿井火药箱/火炮。节点路线与部分计时场景属于既定改编，应与完全缺失的事件区分。
- 浏览器抽查本地世界页、地下城目录和厄运北详情：28 分区目录可加载。当前存档的五人准备区显示 **25/5**，并将 20 名公会成员显示为自有队友；截图已在本次对话留证。尚未以新存档重建该状态，不能断言是持久化污染，需检查 `selectedDungeonMembers` 直接回退 `s.party` 与活动团本状态的关系。

## 物品来源、资源与导航待办

初始无地点来源项 308 个；已剔出 233 个可由当前制造/拍卖目录提供的引用，避免误报“物品不存在”。这 233 项涉及 171 个任务，主要是任务导航未提供制造/拍卖路线。

剩余 **75 个引用，涉及 66 个任务**仍需分类；包括钓鱼世家、物品组合、任务召唤、特殊剥皮与节日物品。这里可能包含已由职业能力获得的例外，例如灵魂碎片，因此它们是人工复核清单，不是 75 个确认缺陷。源物品的“存在于掉落表”也不等于掉落者真的能战斗、条件真的能满足。

四类地图/肖像/战斗模型清单共扫描 9,279 个去重本地资源路径，其中 **27 个 portrait 元数据路径指向不存在的 `creatures/molten-core/*.webp`**。当前 `battle-models.js` 从 npc-models 清单重新解析头像，而非直接读取这些 portrait 字段，因此这是已确认的清单一致性问题，不应直接描述为 27 张运行时破图。

建议修复任务链前先保留这组失败基线。不要通过删除功能断言把回归变绿；对于已确认过时的文案、数量、随机距离与测试收集规则，应按当前需求更新。

## 可重复执行与下一步顺序

```powershell
node scripts/audit-world-content.mjs
node scripts/validate-world-playability.mjs
node --test --test-reporter=tap
npm run typecheck
npm run data:check
```

`audit-world-content` 只输出候选清单，不因候选存在返回失败；`validate-world-playability` 对预期可玩行为做断言，当前 9 项失败，修复后应逐项转为通过。

推荐处理顺序：

1. 修复目标可执行性、区域归类与 2201 等断链交付，建立每条公开任务的接取—推进—交付检查。
2. 统一专业键和条件解释器，明确阶段/节日白名单及依赖闭包。
3. 修复驯服；厘清暴风雪与出生距离回归；更新过时测试和测试收集范围。
4. 对 55/50 端点缺失和 75 物品来源候选逐项标记修复、改编或明确排除。
5. 实现已承诺的副本专属事件，再安排各分区按推荐等级真实全程通关。

验证边界：没有逐条人工通关 3,837 任务，没有重新执行生产构建，没有全浏览器/移动端视觉验收；6 个真实 PostgreSQL 并发测试因缺少对应测试数据库配置跳过。当前本地页面的少量抽查不能替代完整 UI 验收。以上报告是全量静态关系扫描、全仓自动回归和重点运行时复现的结果，不是“全游戏零遗漏”认证。
