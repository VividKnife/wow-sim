# 战斗预计算 CPU 优化

日期：2026-09-21。

本次只优化属性与展示计算的重复工作，保留 100 ms 模拟步长、完整回放帧、战斗规则、随机数和结算结果。

## 原因与改动

五人队对三个敌人的样例需要预计算整场 41.9 秒战斗，并生成 419 帧回放，不是只处理一次攻击。CPU 采样显示热点是 `stats` 中重复展开每件装备的属性和被动法术字段、属性面板反复创建本地化数字格式化器，以及技能各字段重复解析同一组天赋。

- 装备模板的固定属性和被动效果按模板对象预先整理，使用 WeakMap 保存。每次调用仍检查当前装备与耐久，重新计算附魔、增益、天赋和其他动态状态，不缓存角色的最终属性。
- 角色、职业、宠物等级基础表建立索引，保留首条匹配记录的语义。
- 属性面板复用一个 `Intl.NumberFormat`，保持中文数字格式一致。
- 一次技能信息计算内共用被动天赋列表，不跨调用缓存动态天赋状态。

内容模板在运行期间视为静态数据；内容更新应重启进程。

## 测量

运行 `node scripts/benchmark-combat-playback.mjs`。脚本会报告 CPU、Node 版本、一次冷运行和三次预热后计算时间，重复结果一致性检查放在计时区间外。样例沿用原有合成人物与技能配置，不代表生产玩家的技能分布。

环境：Windows、Ryzen 9 9950X3D、Node v24.11.1。前后顺序测量，没有同时运行测试。优化前通过临时模块加载钩子恢复本次修改前的三个规则文件，保留工作区其他变更。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 预计算三次平均 | 3,324.98 ms | 1,608.11 ms |
| 三次测量 | 3,351 / 3,320 / 3,304 ms | 1,633 / 1,582 / 1,609 ms |
| 冷运行 | 3,537.79 ms | 1,799.75 ms |
| 实时模拟及快照序列化，单次 | 3,088.00 ms | 1,757.53 ms |
| 游戏内战斗时长 | 41,900 ms | 41,900 ms |
| 回放帧数 | 419 | 419 |
| 回放未压缩字节 | 602,661 B | 602,661 B |
| 回放离线 gzip 字节 | 54,691 B | 54,691 B |

预计算耗时减少约 51.6%，吞吐约为原来的 2.07 倍。早先单次测量约 3.9 秒，运行状态会造成波动；比较以这组相同预热口径的数据为准。

这些时间不包含数据库、网络与压缩 CPU，也不是 2 核服务器的并发压测。串行 worker、数据库读写和任务排队仍会限制实际承载量，不能把计算提速比例直接当作整机用户容量提升比例。

## 验证

- 与修改前保存的基准结果对比：初始投影、全部 419 帧回放、最终权威状态在 JSON 数据层完全一致。
- 回放逐帧一致性、属性面板、装备耐久与附魔变化、光环失效、宠物属性和天赋相关测试：50 项通过。
- `npm run typecheck` 通过。
- 全量测试存在 7 项失败，涉及猎人驯服/训练、暴风雪、个人战斗出生距离和变羊目标选择；恢复优化前实现后复现相同 7 项失败。本次未修改这些行为。
