# 生活职业学习与升点

当前实现以 `packages/game-domain/src/rules/professions.js` 为统一规则入口，账号服务的制造、采集订单以及线上常驻模拟的动作入口复用该规则。配方和训练阶级来自 `professions-reference.json`。

## 学习与进阶

- 共 12 项：采药、采矿、剥皮、炼金、锻造、制皮、裁缝、工程、附魔，以及副职业钓鱼、烹饪、急救。
- 普通角色最多两个主要专业，三个副职业不占主要专业名额；采用 companion 成长策略的队友最多两项生活职业。
- 在 town、city、outpost 地点学习及进阶，不限制阵营。每项新职业从 1/75 开始。
- 后续上限为 150、225、300，按该职业阶级数据逐级检查角色等级、基础熟练度和费用；不可跳级。学习失败不扣款。
- 达到配方要求后自动解锁，无需单独购买配方；需要专精的配方还必须满足专精要求。

## 升点

- 每次制造尝试升 1 点，批量制造逐次判定，过程中跨越颜色阈值会立即使用新的概率。
- 基础熟练度低于 yellow 阈值：100%；低于 yellow 与 gray 中点：75%；低于 gray：25%；达到 gray 或当前训练上限：0%。
- 种族加成用于配方和资源的准入；颜色、升点概率、进阶门槛使用基础熟练度。工坊显示种族加成与有效熟练度。
- 达到当前上限仍可制造、采集，但不升点；工坊给出封顶提示，“可提升”筛选不返回无法升点的配方。
- 采药、采矿、剥皮按资源要求加 25 / 75 作为 yellow / gray 阈值。采矿不能只靠熔炼一路升至 300，中间需要采矿。
- 当前钓鱼为模拟简化规则：每次成功采集升 1 点，直到所学阶级上限。
- 分解装备可提升附魔至 75，后续需制造配方升点。

## 活动与资源

- 制造订单预留材料和工具，结算后产出与升点共同保存；召回归还预留资产。数量必须为 1–100 的整数，有冷却的配方限 1 次。
- 背包未锁定材料可直接使用，银行材料需取出；工具不消耗。自动补购受市场库存、金币及绑定规则限制。
- 每个资源点每轮可采 2–5 次，每次耗时 3 秒，耗尽后 5 分钟刷新；采集次数、刷新时间和熟练度随角色保存。

### 线上工坊加载失败修复

常驻模拟服务的 `ResidentGameService.snapshot()` 返回 `state: null`，完整角色位于 `response.snapshot.player`。原 `/api/game/workshop` 直接使用 `snapshot.state`，制皮等有配方的职业因此返回 HTTP 500。现统一通过 `gameResponse()` 获取完整角色投影来报价；该投影包含背包、银行、种族、专业、市场库存及冷却字段，报价不读取旧数据库快照。

同时补齐常驻模拟命令协议中的 `craft`、`gatherResource`、`gatherAll`；原协议缺少这三项，会在到达规则引擎前拒绝制造与采集。

新增 `apps/game-server/test/resident-workshop.test.ts`，使用真实 HTTP → ResidentGameService → SimulationClient → worker 链路：修复前稳定重现报价 HTTP 500；修复后验证九个有配方职业加载、制皮学习/自动补购/制造/升点、采药学习/单次及自动采集/停止，以及身份隔离和内容版本检查。该测试连同服务器、内容投影回归共 39 项通过。

全项目回归另记录 2257 项通过、24 项失败（其中 1 项是主动终止运行超过 6 分钟的 `molten-core-route.test.ts` 文件，其余 23 项为断言或模块加载失败），因此不能视为全量通过。失败集中于战斗、装备、团本、资源和模拟时序；用 HEAD 中修改前的职业、工坊、服务及活动实现复测 combat-area / party / scene-presentation / stockades-aura-effects，仍复现其中 8 项失败。本次未扩展修改这些模块。线上相关接口修复后另行运行的 39 项回归全部通过。
