# 世界页沉浸视角 Demo

运行 `node apps/web/scripts/serve-world-scene-preview.mjs`，打开 http://127.0.0.1:5194/world-scene.html 。独立内存角色，不读取或写入玩家存档。预览按钮可切换待机、奔跑、骑乘、鸟点飞行、战斗、长袍和地区；练习战斗会自动补充生命与法力，留出观察时间。

## 当前实现

- 正常世界页在玩家状态下方显示固定高度的场景，经典主界面复用同一组件。探索使用 45 个区域和 30 个副本分区的本地截图；图片加载失败时回退地区配色的 SVG 示意背景。背景支持步行、骑乘、飞行循环运动，详见 [场景背景说明](scene-backgrounds.md)。
- Wowhead Classic 原版角色、种族、性别及实际装备快照。装备变化重建查看器，动作变化通过同源消息更新，不重建 iframe。上游不可用时提示并允许重试。
- 待机 `Stand`、旅行/护送 `Run`、死亡 `Death`。鸟点飞行使用 `Fly`，骑手挂载在飞行兽上；到站恢复待机。飞行兽根据出发地的服务选择狮鹫、双足飞龙或角鹰兽，不按玩家阵营限制。德鲁伊变形尚未接入。
- 固定版本 `c3f890f` 查看器的 `mount: {id: displayId}` 会自动把骑手挂到坐骑 attachment 0，并把骑手动作设为 `Mount`；发送 `Run` 则让马奔跑。普通马、迅捷马、20 级赠送马和现有圣骑士/术士坐骑已有对应显示 ID。显示 ID 从当前物品召唤法术 → creature → ModelId1 提取。
- 镜头固定在背后偏侧、45° 俯视第三人称，骑乘时拉远，飞行使用独立翼展构图；按模型包围盒和视口比例计算取景距离，窗口缩放后重新构图。查看器 Z 轴向上，zenith=135° 才是向下俯视45°。场景按钮可暂停动作；支持减少动态效果设置，离屏/后台保留原查看器释放策略。
- 遭遇战在同一窗口复用 `Battle` 的 embedded 模式，沿用本地模拟/回放、时钟、战斗演出和角色选择。等待战场就绪后淡入，战斗结束回到探索，也可展开完整战斗面板。

## 边界

地区截图是代表性环境，循环运动不表示精确地形。探索使用联网换装模型；战斗仍使用已有本地职业 GLB，尚未让战斗模型同步每件装备，也没有实现同一相机和同一渲染器的一镜到底。第一次加载装备、坐骑或战场仍需要素材准备时间，上马及换装会重建查看器。场景暂停只暂停演出，不暂停游戏时间。

参考：现有 [Wowhead 接入记录](../research/import/wowhead-model-viewer.md)，以及官方 [Classic Dressing Room](https://www.wowhead.com/classic/dressing-room) 的固定版本脚本。未新增模型下载依赖，资源代理只增加固定来源的数字 NPC 元数据路径。

## 验证

`node --test apps/web/test/world-scene.test.mjs apps/web/test/model-viewer.test.mjs`：17 项通过，覆盖桌面/手机镜头包围盒投影、动作优先级、死亡/战斗/飞行、坐骑映射、背景分类、装备槽位、资源代理与失败处理。Web TypeScript 检查通过（仓库数据体积需要提高 Node 堆上限）。新增组件、模型桥接、demo 与启动脚本的 ESLint 通过；现有 `battle.tsx` / `world.tsx` 仍有原有的 any 和 React hooks 规则告警。

浏览器截图实测确认：背后待机、奔跑、马匹与骑手骨骼联动；学徒长袍切到法纹长袍，外观和法力上限同步变化；原位淡入本地 3D 战场及返回探索；铁炉堡雪地配色；390px 视口下无横向滚动。浏览器新加载未观察到运行时错误，现有 Three.js 战场会输出 Clock 弃用提示。

## 骑乘性能修复

原 demo 每 100ms 在页面主线程运行 `advance`、`view` 和客户端投影。20 次骑乘样本平均耗时 310ms、最大 380ms（本机 Node 测量），持续阻塞渲染。已把演示模拟、操作和投影整体移入 `world-scene.worker.ts`，按真实经过时间推进；探索每 500ms 更新、待机不空转，页面不可见时停止推进。主线程只收取投影并绘制，卸载时终止 Worker，命令错误返回 UI。性能折叠面板可查看当前页面 RAF 采样，并不等同于 GPU 渲染耗时。

新增飞行航程条、俯视地形和云层移动；尊重暂停与减少动态效果。demo 的「鸟点 · 飞行」调用真实 `fly` 操作，暴风城至铁炉堡扣除正常费用；「抵达鸟点」通过引擎推进至航程结束。

本轮浏览器确认狮鹫飞行、真实航程结束后铁炉堡待机，以及手机宽度下翼展完整且无横向溢出。骑乘页面 RAF 采样约 141–143 FPS，最长帧约 14–21ms（本机高刷新率环境；非跨设备帧率保证）。

## 浏览器模型缓存

查看器 iframe 内注册 `/model-viewer/` 窄作用域 Service Worker，只拦截同源 `/api/model-viewer/` 的 GET 请求。CacheStorage 保存成功且标为 public 的资源，遵循响应 max-age（最长 24 小时），最多 128 MiB / 256 项，单个资源最多 16 MiB；串行写入并淘汰最旧条目。缓存使用独立版本名，不缓存错误或不完整装备响应，存储禁用、配额不足时回退网络及原有 HTTP 缓存。不包含游戏存档或用户资料。

切换坐骑/换装保留 iframe 和查看器脚本，动作切换继续复用当前模型。坐骑/装备变化仍重建模型实例，因此缓存减少下载与脚本初始化，不保证零 loading；首次资源、过期资源、浏览器清理站点数据后仍需联网。jQuery 继续使用原有 CDN HTTP 缓存。后台/离屏仍释放 iframe，返回时可复用磁盘资源缓存。

调试时可检查 iframe 的 `#viewer` 元素：`data-cache-hits` 记录 fetch/XHR 命中持久缓存的次数，`data-render-count` 记录同一 iframe 内重建次数。缓存策略依据 [MDN ServiceWorker 注册与作用域说明](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register)。新增 5 项测试覆盖跨客户端缓存、失效、失败响应、并发容量淘汰和存储拒绝。

缓存版浏览器复测：待机 → 骑乘 → 待机沿用同一个 iframe（render count 1 → 2 → 3），缓存命中计数 32 → 64 → 96，模型均加载成功。22 项模型/场景/缓存测试、TypeScript 和本次修改文件 ESLint 通过。

## 正式游戏接入

正式入口 `Game → World → WorldScene` 使用当前角色状态及内容投影，自动驱动装备、骑乘、旅行和飞行，不使用 demo 的临时角色或自动回血。世界页内战斗启用本地 Worker 的实时战斗帧，服务端回放也按观战频率同步；世界状态栏继续接收每秒概览。世界页狩猎及任务伏击不自动打开战斗弹窗，玩家可主动展开；地下城和团本保留现有弹窗流程。

展开完整战斗时暂停内嵌战场的订阅与渲染；收起后恢复。切换角色以角色 ID 重置场景状态。公共模型资源代理及 Service Worker 同样用于正式 Next.js 入口。本轮验证本地正式游戏已显示当前角色及真实装备；原位战斗入口策略加入回归测试。线上发布另走项目现有发布流程。

接入验收：24 项模型/缓存/场景/战斗入口测试通过，Web TypeScript 检查通过。浏览器确认正式世界页显示当前角色外观；共用场景的战斗展开后底层 canvas 数量为 0，关闭弹窗后恢复原位 3D 战场。
