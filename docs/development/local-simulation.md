# 本地模拟与战斗渲染

实现日期：2026-09-21。

网页自动接管运行中的个人活动和只有一个真实账号参与的实例，包括核心队、佣兵和 25 人公会远征。计算复用 `packages/game-domain/src/rules/engine.js` 的 `advance`；没有第二份伤害、AI、随机数或掉落规则。多人实例继续由服务器推进。个人旅行、恢复等衔接过程也在同一个本地会话里推进，避免遭遇之间反复切换执行者。

## 执行与存档

1. 游戏快照发布 `localSimulation` 候选信息。浏览器通过鉴权的 `POST /game/local`（Web 代理 `/api/game/local`）申请会话。
2. 服务端核对账号、参战角色、内容版本和执行权，返回完整规则检查点、随机状态、服务器时间及离线期限。只有取得执行权后才加载浏览器 Worker 的规则代码和静态数据。
3. 活动或实例的 `nextEventAt` 设为调度暂停值。后台推进和回放准备同时检查 `localSimulation`，即使先前的 worker 已读到任务，也不能覆盖本地接管后的状态。
4. Worker 按原有 100 ms 规则步长推进，每个计算批次最多 20 ticks，批次间让出消息处理机会。实际时间用服务器锚点加 `performance.now()`，不使用页面系统时钟决定收益时间。
5. 通常每 10 秒提交一次检查点，遭遇/活动切换时提前提交。服务器信任战斗结果，校验结构、角色、会话、序号和时间后，通过既有资产持久化与结算事务保存收益，**不重算整场战斗**。
6. 定期提交不暂停模拟。确认返回后在 Worker 内合并服务器分配的新物品 ID；之后发生的伤害、移动、消耗和掉落保持不变。换装等服务器指令和角色切换会先暂停并提交最新检查点，再执行操作；实时战斗指令直接在本地执行。

尚未被网页接管的活动继续使用现有服务器执行路径；现有 recorded 回放仍用于这一服务器运行场景。已接管的单人活动即使页面关闭也不会自动回到服务器逐场模拟。后台采集、制造和多人规则不变。

## 并发与恢复

- 每次申请发放新的会话 ID；30 秒执行租约防止两个页面同时接管。检查点顺序从 1 开始，每次提交必须匹配当前会话与序号。过期会话可被另一页面接管，旧结果会被拒绝。
- 每次上传使用固定 requestId 和请求摘要。网络失败保留原请求重试；检查点回执只包含会话信息及物品 ID 映射，不包含完整 state，并持久化用于重复投递。每个连续会话仅保留最新响应；claim 仍返回完整可恢复状态。
- 指令使旧会话失效，接下来从指令执行后的服务器检查点重新申请。调整策略、拾取、换装等操作沿用原有领域校验。
- 页面退出尝试用小型 keepalive 请求释放执行权；不依赖卸载事件保存大体积战斗状态。正常刷新可以马上重新申请；浏览器崩溃或释放请求失败时，另一页面最多等待剩余租约时间。
- 刷新、设备切换从最后确认的检查点重放未提交时间。随机状态已保存，重放不重新抽取已确认收益。未提交的画面可能暂时回到检查点，不会重复结算。
- 离线时间在回到页面时分批补算。默认最多两小时；本地会话独立记录最近确认时间，普通快照心跳不能无限延长已停止的浏览器的离线额度。超过额度的墙上时间被跳过，游戏内计时器不平移。
- 手动操作不再依据上一份画面的落后毫秒数直接拒绝。Worker收到操作检查点请求后固定结算目标（受离线额度限制），按每批20 tick补算到目标，暂停并提交检查点，再自动执行操作；不持续追逐移动的当前时间。后台页面同样可以完成这一交接。请求同时校验会话和requestId，旧响应不能提前放行操作。补算有实际时间进展时续期响应超时，停止推进15秒仍报错；引擎失败保留原始原因，不再被离线提示遮盖。
- 内容版本不一致时停止申请/提交并提示刷新；过期活动不做存档迁移。

该模式按当前产品假设信任客户端结果，不提供反作弊验证。资产归属、事务回滚、重复提交和正常网络故障仍有检查。

## 渲染与资源

- 模拟、战斗投影、角色面板计算均在 Worker 内完成；闭合的战斗窗口不接收高频战斗投影。
- 战斗窗口通过独立外部订阅接收约 10 Hz 投影，Three.js 继续在显示帧上插值移动、弹道与镜头。单个已知样本最多向前显示一个规则 tick，失联时不会无限演出虚构的战斗。
- 其他页面最多每秒更新一次；战斗窗口打开且遭遇未改变时不刷新整个 Game 组件。遭遇结束仍立即发布完整页面状态。
- 伤害统计每 500 ms 更新一次，结束时立即刷新；策略面板使用低频的页面状态，不跟随每个战斗帧重算。
- 镜头取景按新位置样本或尺寸变化计算，逐显示帧只做插值，复用目标向量。
- 本地会话中的服务器快照轮询降至 60 秒。页面不可见时停止画面投影，模拟仍按小批次推进；浏览器挂起后按检查点恢复。

当前 Worker 包含完整的规则目录和静态内容，生产构建约 40.84 MiB（离线 gzip 测量约 3.56 MiB，不代表部署已开启相同压缩）。它在取得执行权后才加载，并使用构建哈希缓存；首次加载与移动设备内存仍是后续按内容拆包的优化点。

## 2026-09-26：完整单人接管与即时指令

- 单账号实例按真实账号数量判定：NPC 小队、25 人金团均可本地执行。竞技场和战场继续使用同一个本地执行协议；多人实例仍留在服务器。
- Web 的服务器命令始终带 `localClientId`。新建个人活动或开始单账号实例的同一事务即预留本地执行，将任务从后台调度中移除。首次 Worker 下载和 claim 期间不会抢先生成回放或计算战斗；不支持浏览器执行的调用方仍可使用服务器路径。
- `cast`、`petCommand`、战中 `combatCommand`、`raidOrder`、`battlegroundOrder`、撤退与 PVP 投降直接由 Worker 调用共用 `act`。角色、命令范围、场次和技能规则仍校验；输入固定到接收时的模拟目标，落后时分批追赶。指令失败不会修改运行状态，也不会重新发给服务器执行。
- 实时指令绕过网络保存队列。慢上传或临时网络失败不暂停战斗；确认后只合并正式物品 ID。换装备、调整名册和其他服务器操作仍在最新检查点之后执行。战斗操作引起结束时立即更新界面并安排保存。
- Worker 使用共用引擎的 `advanceOwned` 推进自己独占的状态，避免每 50 ms JSON 复制全存档。事务、录制和其他调用方仍使用会复制输入的 `advance`；规则循环只有一份。上传检查点另做独立复制，不能随下一帧变化。
- PVP 场次／阶段变化立即发布完整快照，团本指挥状态进入低频战斗帧，指令后立即刷新。常规账户快照轮询从 10 秒降为 60 秒；检查点仍每 10 秒提交，遭遇边界提前提交。此降频仅指快照查询，不包括保存请求。
- 经典界面的暂停／继续按钮靠近队员名称，避免被右侧伤害统计面板挡住。

可运行 `node scripts/benchmark-local-simulation.mjs` 对比复制与独占推进；它测量 50 ms 调度、15 秒游戏时间的规则计算，不包含网络、数据库、完整面板投影和 GPU 渲染。`local-simulation-owned.test.ts` 逐样本比较野外、五人本、25 人团本、5v5 竞技场和 10v10 战场的完整序列化状态。


## 2026-09-26：单人检查点的数据取舍

`rules/local-checkpoint.js` 是浏览器上传与服务器存储共用的投影。先剔除临时字段，再复制，避免仅为上传而深拷贝最近 20 场战斗。服务端再次执行投影，即使调用方上传了完整历史也不会落库。

| 数据 | 策略 |
| --- | --- |
| 逐条战斗日志 `logs`、历史战场快照 `battleHistory` | 仅保留在当前本地 Worker；检查点中为空数组，队员和 NPC 居民的副本同样裁剪 |
| 竞技场日志、战场事件与短暂显示特效 | 本地展示，不上传、不持久化；事件序号保留，避免恢复后 ID 重复 |
| 血量、资源、位置、冷却、施法、弹道、持续效果、AI、随机数 | 保留，支持正在进行的战斗恢复；弹道和持续效果会产生伤害，不能当作纯视觉数据删除 |
| 当前统计、最近一场结束状态 `lastCombat` | 保留；副本路线、任务与金团结算仍读取这些数据 |
| 角色成长、金币物品、任务、副本进度、金团拍卖/分金、NPC 成长、PVP 比分和结果 | 保留 |
| 核心旅程记录 `journey` | 保留原有最多 100 条摘要；战斗详情不跨重新载入保存 |

检查点响应改为 `{ownerId, session, itemIds, serverNow, contentVersion, deadline, active}`，`itemIds` 是 `[临时ID, 正式ID]` 数组。Worker 只按 ID 修改后续状态中的物品引用，不回写旧血量或时钟，也不清除当前本地日志。失败重试仍使用同一个请求；服务端最新回执保证正式 ID 和收益不重复生成。claim 接管时才下载完整规则状态。

普通周期保存不再创建 `settlements` / `outbox` 的 `localCheckpoint` 或 `instanceSettled` 记录。实际金币与物品变更继续写 `ledger`，个人活动完成写 `localCompleted`，实例完成写 `instanceSettled`。多账号服务器实例的事件路径保持原有语义。10 秒检查点与遭遇边界保存频率不变，以免通过延长间隔增加未保存进度。

代价：重新载入页面、切换设备或从服务器重新接管后，旧逐条日志和历史详细战报不恢复；最近战斗结果与核心旅程摘要仍在。旅程页面已说明该策略。未实施历史数据迁移或清库。

验证：`local-checkpoint.test.ts` 对五种场景从第 5 秒检查点恢复至第 15 秒，与连续执行的持久状态逐字段比较；服务测试覆盖数据库中无临时历史、连续保存只有一个小回执、无周期通知堆积，以及正式掉落 ID 的重复提交。可用 `node scripts/measure-local-checkpoint.mjs` 重现未压缩 JSON 体积测量。

## 2026-09-26：过期活动调度与同步故障

线上诊断发现 worker 持续重新选中同两个规则版本不匹配的个人活动和副本，每秒反复报告内容版本不可用。客户端接管旧团本返回 HTTP 409 / `CONTENT_VERSION`；账户和存档查询仍可返回 200。这是已确认的无效后台工作来源，不能据此把服务器全部 CPU 使用率归因于该问题。

到期队列现在在数据库查询和 LIMIT 之前筛选当前内容版本，避免加载过期模拟、抢占实例租约和反复报错，也避免旧活动占满批次而饿死当前活动。旧活动保留原状态，玩家通过已有“脱离卡死”流程结束它；不迁移规则状态，也不让滚动发布中的旧 worker 修改新版本活动。

客户端保留结构化错误码，区分规则过期、登录失效、数据库繁忙、请求超时和服务错误。接管失败后降低账户快照轮询至 60 秒；当活动或角色发生变化时清除本地失败标记，恢复本地接管。首次存档加载失败的页面也提供脱离入口。脱离会取消当前活动、保留已保存资产，未结算收益不补发；线上不自动执行。

回归覆盖 MemoryStore / PostgreSQL 版本筛选先于批次限制、不修改过期活动和租约、新版本活动正常推进、旧活动脱离，以及客户端失败后无重复 claim 和新活动恢复。
