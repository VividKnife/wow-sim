# 前端内容加载

公共展示资料通过 `/api/game/content?version=<contentVersion>&pack=<name>` 读取。禁止让 HTTP 接口直接返回服务端 `clientContent()` 聚合目录。聚合函数用于服务端索引、离线预览及测试，不属于浏览器传输协议。

| 内容包 | 加载时机 | 范围 |
| --- | --- | --- |
| `core`（默认） | 进入游戏 | 创建选项、附魔/消耗品说明、地下城和首领索引；没有完整物品表、市场商品或首领掉落 |
| `items&ids=118,6948` | 快照出现新物品引用、选择角色、查看配方 | 最多 200 个 ID；同时返回明确的缺失 ID |
| `market` | 打开拍卖行 | 当前市场商品及这些商品的展示资料 |
| `boss:<dungeonId>:<bossId>` | 打开一个首领的掉落 | 该副本内该首领的掉落 |

同版本内容包可由浏览器/CDN 缓存一年。ETag 根据具体响应生成，不能用一个版本号替代所有包的 ETag。请求版本不匹配返回 409；未知包返回 404；无版本请求不缓存。压缩取决于部署层设置，容量脚本里的 gzip 数值不等于实际网络传输实测。

`content-loader.js` 集中处理请求去重、15 秒超时、失败重试、版本校验和物品缓存。内存最多保留 64 个请求结果、两个版本的物品目录；同版本已确认不存在的 ID 也被缓存。物品依赖从展示快照的 `id/item/itemId/healthItem/manaItem` 收集；与其他实体重名的数字字段可能多取少量无关物品。新增其他形式的物品引用时必须同步扩展收集器和测试。

服务端快照先补齐所需物品再发布给 UI。本地 Worker 的总览快照也先补齐展示资料，并验证它仍是当前角色的最新快照；等待物品期间模拟及独立战斗帧继续推进。配方只请求当前分页所需的成品、材料与工具。角色选择只请求当前装备，不再请求完整目录。

任务快照仅发送已接任务、当前可接和可交付任务，包括随身物品触发任务。服务端及 Worker 内部仍保留完整任务规则，以保证任务前置、奖励和导航正确。

世界、角色、队伍、地下城、竞技场和战斗面板采用动态代码导入；图片、地图、GLB 和音频继续由实际展示/播放触发。内容包只传资源地址，不主动预取地址指向的文件。

## 扩展约束与验证

- 新增区域、任务和怪物不要塞进 `core`。当前动态资料随所在地快照发送；未来较大的区域静态展示资料应添加独立内容包。
- 新增副本沿用首领索引与掉落分离；同一个包必须只包含该范围依赖。
- 若市场显著扩大，应把市场搜索和商品列表改成服务端分页；当前市场为一个按需包。
- 浏览器本地模拟 Worker **仍静态导入完整规则及模拟数据**，本次没有实现模拟数据按区域卸载。未来全世界规则扩展时，需要进一步拆分模拟数据注册与依赖声明；不能仅凭展示包已拆分就认为 Worker 也完成分区。
- GLB 继续按遭遇加载，但本次没有做模型压缩或 GPU 缓存淘汰。

运行 `npm run content:measure` 查看原始/gzip 体积；基础包上限 150,000 字节，测试还限制其 gzip 在 40,000 字节以内。运行 `node --test apps/web/test/content-packs.test.mjs apps/web/test/client-snapshot.test.mjs apps/game-server/test/server.test.ts` 验证作用域、并发请求、版本隔离、重试及 HTTP 缓存。

规则或内容发生变化后执行 `npm run data:compile`，并重新构建前端，使服务端和 Worker 使用相同版本。
