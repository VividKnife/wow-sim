# 战斗策略与队伍站位

策略页面按成员配置；「一键应用推荐」立即保存所选模板的施法规则、职责、战前增益和药水设置，不修改天赋加点或学习技能。

- 模板覆盖九职业的 27 个天赋分支，野性德鲁伊额外提供熊坦模板，共 28 个。根据当前投入最多点数的天赋树推荐，未加点时使用职业默认分支。
- 模板以 20 级技能组合设计，只加入角色已经学会的技能，并选用同名最高已学等级；未学会的天赋主动技能不会加入。
- 技能选择器可搜索中英文名称，显示图标及等级。服务端同样限制为已学、受支持的主动技能，剔除被动、天赋被动节点及独立的非战斗操作。
- `enemyFar` 为角色与当前技能目标的二维距离严格大于阈值。满足条件后仍须通过技能本身的最小/最大射程检查。
- `allyHealthBelow` 检查本场参战的存活友方（包括施法者）。治疗模板使用这个条件响应队友受伤。
- 职责可选自动、坦克、近战输出、远程输出或治疗。自动判断使用职业、天赋和德鲁伊形态。

多人战斗中，远程/治疗按实际技能射程接近目标，安全时保持站位。移动遵守真实速度、定身与控制；正在施法时不强制移动。治疗救急、已配置的贴身控制和打断可优先于走位。短射程技能可在敌人靠近时使用，不会让后排主动冲进近战。缺蓝或技能冷却期间不会回退为追击近战。

坦克优先处理正在攻击后排的敌人，再处理其他脱离坦克的敌人，继续使用实际移动、技能射程、嘲讽冷却与仇恨结算。因此站位是行动目标，不能保证被定身、失去坦克或敌人突进时始终安全。

实现入口：`strategy-presets.js`（模板）、`combat-strategy.js`（技能和条件校验）、`combat-roles.js`（职责）、`combat-positioning.js`（走位）、`apps/web/app/strategy.tsx`（编辑器）。策略经角色/副本现有持久化路径保存；死亡后仍可编辑策略。

验证涵盖模板覆盖与天赋推荐、最高等级/被动过滤、距离边界、猎人射击盲区、后排走位、控制后撤、坦克救援，以及副本策略保存并重新加载。

### 条件与执行顺序

每条规则的主条件与 `and` 数组（最多 3 个条件）必须全部成立。新增目标/自身生命下限、当前目标连击点下限、宠物生命、正在被攻击、开战秒数、本场存活敌人数上限。人数上限包含受控敌人；技能范围人数使用真实范围且排除被控制成友方的单位。多重射击以目标为中心 10 码并受实际射程限制，最多命中三名敌人。

变形模板仅在最多两名敌人时控制副目标，避免三怪羊掉一只后把群攻永久封锁。有其他成员正在维持控场时，范围内存在受控敌人会阻止群攻。资源不足会继续检查下面的规则。

暴风雪开始引导后保持原地面范围，不再因仇恨转移、技能优先级或新出现的控场重新选择技能。范围内没有存活敌对目标，或施法者受到未被完全吸收的直接攻击伤害时，立即停止引导；持续伤害不触发此中止。正常引导结束、死亡和强制控制仍按战斗机制处理。

配置列表按条分派给各技能处理器，保证通用技能、法师技能与战士/盗贼/牧师核心技能共同遵守优先级。走位前仍可执行已配置的贴身反应、打断与治疗救急。牧师的未配置自动治疗仅作为无治疗规则时的默认队友行为。

新增 `strategy-scenarios.test.mjs` 用实际战斗 tick 检验群攻命中、控场保护、治疗阈值、资源恢复、处理器顺序、持续效果刷新和条件投影。

## 团队开怪等待

副本点击「推进并迎战」后立即创建当前遭遇并打开战斗房间，不再等待路线行进、自动补给或自动增益；需要恢复时在推进前使用休整与补给。房间内统一倒计时 3→2→1，期间双方不移动、不施法、不攻击。倒计时结束后，存活坦克按策略释放开怪技能，没有可用技能则走近敌人；其他成员等待坦克先手，敌人在坦克敌对行动或进入近战距离后开始应战。没有存活坦克时倒计时后正常开始，避免卡住。`combat.pull` 保存开怪时刻及接战时刻，随客户端快照与存档保留，每次重新迎战重置。副本的输出等待和开场时间条件从倒计时结束计算。野外自动增益与补给流程保持原有行为。

有存活坦克参战时，非坦克成员默认开启等待坦克策略，开场等待 `pullDelaySeconds`（默认 3 秒，界面可设 0–10 秒），随后要求每个受影响敌人正在攻击坦克且已有真实坦克仇恨。单体技能、群攻、主副手平砍、自动射击、宠物与攻击图腾共用等待约束。治疗、增益和变形控场不受输出等待限制。没有参战坦克、坦克死亡或明确关闭等待时，不会一直停手。

倒计时基于当前战斗 `startedAt` 和模拟时钟，因此存档恢复不会重置，每场新战斗重新开始。新遭遇由坦克接敌，不直接注入虚假仇恨；坦克会优先补打尚未建立自身仇恨的怪物。远程已经被追击时向坦克移动，并在 8 码内停留等候救援，不继续向外风筝。怪物被重新拉住后恢复正常后排站位。

`apps/web/test/tank-pull.test.mjs` 覆盖三秒边界、普攻与自动射击、宠物和图腾、群攻逐目标检查、治疗不延误、无坦克退化、重载/新战斗计时、接怪走位以及策略保存与校验。


### 后排移动

队伍远程与治疗在未被追击时保持站位，不按固定 23–30 码距离带反复前后移动。接近目标由实际技能射程决定；被敌人追击时回靠存活坦克。缺少坦克时，追击者进入 8 码内才触发撤退：以其他存活队员中心周围 12 码为支援区域，超出时回靠，边缘时转向，避免无限直线风筝。死亡队员、宠物、图腾和护送 NPC 不作为支援锚点；没有存活队友时仍可向外撤退。单人战斗保留定身后拉开距离的行为。

法师对正在远离自己的目标读条前，根据上一模拟 tick 的二维移动速度和实际读条时间预留距离；静止、接近中的目标、瞬发及固定地面技能保留正常射程。超距取消后 10 秒内再次攻击同一目标时额外留 3 码余量。需要接近时，可先尝试配置列表中满足条件、可用且已在射程内的瞬发技能，不能越过禁用、条件、冷却或控场规则。完成读条时仍检查真实射程并在成功后扣蓝。取消事件分别记录 `target`、`range`、`strategy`、`resource` 原因。

### 放弃当前战斗

战斗界面的「放弃战斗（全员死亡）」发送带当前 `encounterId` 的 `abandonCombat` 命令；没有战斗或战斗已经切换时拒绝执行。共享副本仅队长可操作，服务端沿用请求幂等机制，重复请求不会重复记死亡或发奖励。

执行后所有参战成员及召唤单位立即死亡，清除施法、弹道、地面效果和待出现敌人，保存本场统计并停止自动狩猎。必须通过已有返回尸体、复活术或职业复活流程恢复后再开战。副本当前路线与已击杀进度保留；未击败敌人再次挑战时从原始生成数据恢复满血，不会凭放弃战斗发放奖励。

### 快照重放

`node scripts/replay-combat.mjs <实例或模拟快照.json> <输出报告.json> [秒数，默认180]` 在内存中运行当前模拟引擎，停止于本场结束或时间上限，不写回数据库。报告包含每位成员的施法、取消、伤害、首次伤害时间、最大位移及事件。原始快照和现场报告保存在被 Git 忽略的 `.cache/combat-replay/`。

最后一只可攻击敌人处于变羊状态时，自动解除策略层的控场保护，允许角色、宠物与攻击图腾正常打醒收尾；变羊本身仍由实际伤害解除。多只敌人存活时继续保护变羊目标。

### 战斗区域

`packages/game-data/data/combat-areas.json` 定义每个场景的战斗区域。`profiles` 中配置 `name`、`shape: "rectangle"`、`minX/maxX/minY/maxY`（战斗局部坐标，单位码），`encounters` 按副本路线 ID 选择区域，`locations` 可按野外地点 ID 覆盖默认区域。死亡矿井的 58 个遭遇分别配置矿道、房间、甲板或船坞；未单独配置的野外使用 `outdoor`，独立副本测试使用 `room`。这些范围为模拟设计值，并非原版地图碰撞网格。

开战复制区域到 `combat.area`，整场固定，结束后保留在战报中。自动镜头以区域取景，金色虚线表示边界。所有参战角色、敌人、宠物与图腾均受限制；普通移动、追击、撤退、恐惧逃跑、闪现、冲锋及生成位置统一约束。移动撞墙时截断越界分量，允许沿墙移动；无法后退的法师继续尝试施法。重拳武器箱目标同样落在区域内，避免阶段永久卡住。

范围当前支持矩形，不处理区域内部的墙壁、障碍物或视线遮挡。旧的进行中快照不补写区域；新遭遇使用新配置。`combat-area.test.mjs` 验证场景配置、四面边界、移动技能、恐惧、宠物、首领阶段、贴墙施法、固定镜头与序列化后的确定性。
