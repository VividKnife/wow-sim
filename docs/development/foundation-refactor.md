## 已落地的基础

| 边界 | 当前实现 |
| --- | --- |
| 身份与组织 | 独立账号、稳定角色 ID、长期伙伴档案、引用式出战名册和跨账号实例名册 |
| 资产与结算 | 独立钱包和物品行、绑定所有权、账本、材料/原工具预留、业务结算键与请求收据 |
| 专业与活动 | 每角色专业上限、现实时间冷却、不同制造执行者/付款者/收货者、采集/制造召回、独立 RNG |
| 服务器推进 | Node API 与独立 worker；持久到期查询，事件化采集/旅行，安静空闲快速推进；战斗保留验证过的步进规则 |
| 共享实例 | 同一权威状态、5/10/20/40 席位、角色执行租约、递增 epoch、防旧执行者写入、按合同幂等扣费、退出清理 |
| 奖励与可靠交付 | 每角色装备奖励资格，不重复发主角金币/经验；经济事实和 outbox 同事务，inbox 投递去重 |
| 持久化 | PostgreSQL JSONB 实体行、生成索引列、钱包约束、唯一键、串行化事务重试；内存 Store 仅用于测试 |
| 服务入口 | 短期 HMAC 身份凭据；Node 不信任自行填写的身份头；Web 保留认证、同源校验和薄代理 |
| 客户端 | 明确字段投影，隐藏随机种子/收据/执行租约/预生成副本信息；角色切换和迟到响应保护；按需工坊报价和版本目录缓存 |
| 内容与包边界 | 唯一规则实现移到 `packages/game-domain`，原始运行数据移到 `packages/game-data`；SHA 清单同时覆盖 JSON、规则和注册遭遇 |

入口、变量、数据库启动和操作流程见 [运行说明](game-runtime.md)。领域、服务、客户端各线报告保留实施细节；最终验证以本文件和 [独立审查](../superpowers/plans/foundation-review.md) 为准。

## 明确的交付边界

- 已有死亡矿井与北郡通用遭遇运行于新实例服务；大席位是架构能力，没有新增完整 10/20/40 人团本内容。
- 访客能配置自己角色的策略、恢复设置和宠物姿态；手动施法目前复用法师战斗入口，其他职业通过策略运行，未支持的访客命令明确拒绝。
- 浏览器使用带条件请求的 REST 回退同步；Node WebSocket 面向已认证连接，默认完整投影，显式 `mode: "delta"` 提供基础 revision/sequence 校验的增量事件和重订阅快照恢复。实时协议能力与浏览器登录接入分别验证，不能把 Node 测试称为真机联机验收。
- 运行时只加载一个内容版本。旧版本活动停止推进并保留数据；更新规则前应完成活动，或保留能执行其版本的服务，不能静默切换版本。
- outbox/inbox 提供持久投递原语；尚未接入支付、邮件或外部消息总线。
- 本地 SQL 测试验证真实 PostgreSQL SQL/事务和数据库导出重载恢复；外部 PostgreSQL 多进程争用、公网压测、部署和真机验收尚未执行。
