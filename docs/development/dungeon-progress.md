# 副本离开与返回

死亡矿井和暴风城监狱的活动进度由实例 `simulation.dungeon` 持有。队长所属账号离开时，服务器先执行规则层 `leaveDungeon`，将完整路线写入队长角色的 `rules.dungeonSaves[contentId]`，结算成员与资产，再释放角色占用。离开实例和离开副本两个命令使用同一保存流程。

在副本外整理背包、保存角色或重启服务不会删除 `dungeonSaves`。返回时按角色当前装备、背包和队伍建立执行实例，恢复保存的路线，并沿用原 `runId`，保留怪物生成结果、击杀、交互和累计战斗统计。执行实例 ID 可以变化；副本冒险的 `runId` 不变。

路线状态包含 `locationId`（当前位置）、`destination`（`full` 或遭遇 ID）、`path`（指定目的地的剩余遭遇）及 `cursor`（当前待处理遭遇在定义中的索引）。路线允许回头和跨支路，展示进度按 `cleared` / `skipped` 集合计数，不再使用 `cursor` 作为完成数量。只有全部区域处理完才设置 `completedAt`；完成指定首领只关闭自动推进。`dungeonNavigate` 是队长实例命令，战斗中提交时保留当前战斗及其游标，新目的地在当前遭遇结束后生效。离开时目的地和路线照常保存，自动推进关闭。

入场时立即持久化新副本计数并消费保存的进度。返回已有冒险不占新的每小时入场次数；只有明确执行 `resetDungeon` 才删除指定地下城保存的路线，下次进入重新生成副本。进度保存归队长角色所有，不给退出的跨账号访客复制一份独立进度。

回归：`node --test packages/game-domain/test/dungeon-progress.test.ts`，覆盖两种离开命令、背包修改、服务重建、路线及统计保留、主动重置与每小时新副本数量限制。
