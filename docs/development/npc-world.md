# 冒险者大厅与持久 NPC 玩家

更新日期：2026-09-26。

## 入口与玩法

主角18级开放。在「队伍」或「地下城」的组队面板进入，首次进入创建当前存档的50名固定冒险者。已移除自有队友招募、替换、培养与生活职业入口。

大厅显示主角加四个出征席位，只能选择居民池中的 NPC。支持推荐小队、补齐空位和清空名单。推荐从本批、好友、曾经同行和已选 NPC 中按主角职责补齐1坦1疗3输出，优先好友和共同冒险较多的人。出征名单独立保存，野外由主角冒险。

五人副本与金团共用持久居民池。60级金团从所有满级居民中邀请24人，装备、钱包、好友和经历不随开团重置。金团规则见 [金团设计](../design/gold-raids.md)。没有新增真人邀请、跨世界好友或公共匹配。

NPC 档案支持名字/职业搜索、职责筛选、好友星标、好友筛选、实际装备与属性、共同组队次数、近期冒险记录。不同性格有独立台词和推进节奏；不通过性格修改 roll 点数。NPC 自行配装和安排技能，玩家不能替他们改天赋、策略或拿走物品。

## 六人批次与熟人名单

居民池固定50人：战士、圣骑士、猎人、潜行者、牧师各6人；萨满、法师、术士、德鲁伊各5人。昵称混合玩家式命名（如「盾墙还有三秒」「面包管够」）和奇幻姓名（如「洛瑞安·晨誓」「米瑞尔·蓝焰」），身份与姓名不随换批改变。

首次走进大厅生成六人批次，并开始五分钟冷却。手动「换一批」后重新计时；到期不会自行换人，也不累计刷新次数。每批一坦、一治疗、四输出，避开上一批全部成员，优先展示次数较少的人，并在同等次数下优先不同职业。轮换使用独立随机状态，不影响战斗、掷点或个人冒险随机数。服务端按 `wallAt` 校验冷却，浏览器仅展示倒计时；刷新页面、重复请求、服务重启不能绕过。

四个名单入口分别为「本批冒险者」「我的好友」「曾经同行」「已选 NPC」。每页至多六人；名字搜索、职业和职责筛选仅作用于当前名单。好友与已选成员不受换批影响，曾一起进入副本的 NPC 可从曾经同行列表再次邀请。没有见到合适人选时，可邀请熟人或等待下一批，不通过一键推荐遍历全部50人绕过换批。

开发数据结构新增 `npcWorld.board`（名单、展示次数、独立随机状态、下次刷新时刻、批次序号）。遵照项目初期开发规范，不做24人旧存档迁移；已创建旧 NPC 世界的开发存档需重新创建。独立试玩使用新的隔离存储键，并提供「试玩：快进5分钟」用于验证冷却，正式游戏没有快进按钮。

## 装备与成长

身份ID绑定主角存档和居民序号，不随团次变化。首次配装从当前等级可穿戴的绿/蓝装中选取，包含职业、种族、技能和装备组合校验；用初始种子形成配装差异，不在每次邀请时刷新装备。不是对 NPC 过去任务历史的完整还原。

离队成长按20分钟一个汇总事件推进，每次最多补算两小时。低于主角等级时每两个事件追赶一级，最高追至主角等级并更新职业技能、天赋。组队中的真实战斗经验仍按原有规则结算。角色在五人本或金团中不会同时收到后台任务收益；离队任务也会增加少量自己的旅费。

后台任务取自当前游戏有交付地点的任务目录，记录完成任务和可用装备奖励。每三个事件尝试一次副本活动；掉落仅来自主角已击败、已开放五人本首领的目录。40%升级领取率是本作汇总模拟参数，不等于原版掉率。装备只在实际有提升时替换，主角不会收到这些离队收益。世界未提供的高等级区域和完整1—60任务链没有虚构为已实现内容。

NPC 猎人准备适配弓枪的弹药，并从自己的旅费补充；队伍休整仍沿用现有共享补给规则。好友没有送礼维护要求，取消好友不会删角色、装备或战绩。

## 分装

有 NPC 参战时，绿色及以上可装备掉落进入队伍分装；任务装备/任务起始物品保留原拾取路径。没有 NPC 时继续使用原有掉落流程。

- 主角选择需求、贪婪或放弃；其他成员根据实际配装自动判断。NPC 使用同一套职责配装判定。
- 需求比较整套装备的职责收益，包括双戒指/饰品、主副手、双手替换、唯一数量与已有待领取装备。数值评分是本作启发式，不承诺所有特殊触发装备的最佳配装结论。
- 战斗结束后开始60秒等待，超时默认贪婪；达到唯一数量上限则放弃。大厅可开启主角自动按需选择。
- 需求优先于贪婪，同类按1—100点排序，平点使用预先保存的随机顺序。点数与平点顺序在分装前不发送到客户端。
- NPC 需求获奖立即换装并保存；贪婪所得出售补充自己的旅费。主角所得进入自己的待领取列表。
- 分装等待期间保留自动推进意图，选择完成后自动继续。开启自动分装可连续推进。末段掉落未处理前实例不会提前停止调度。
- 未完成分装不能普通离队；紧急脱离对已经提交的掉落按主角放弃处理，其余成员保持原规则，保存获奖者后结束实例。不会重抽或将 NPC 物品转给主角。

## 数据与权限

`npcWorld` 保存在主角角色规则中，包括居民档案、独立随机状态、成长游标、好友、装备、已知副本首领和出征名单。有限居民池不创建50个账号或50套常驻活动。正在参战的 NPC 使用实例内单位，持久化主角时 `syncNpcWorld` 将耐久成长数据写回档案。

实例名册增加 `controller: 'npc'`；其账号字段表示来源存档，不授予玩家对 NPC 的直接控制权。创建 NPC 实例必须由该世界主角参与，主角执行租约锁住整个世界的 NPC 使用权，防止同一 NPC 双开实例。NPC 没有伪装成 Character 或佣兵合同，不影响角色选择器。

有 NPC 的副本由服务端执行，禁用浏览器本地检查点，以保持分装点数和结果在服务端。其余单人活动继续采用现有本地执行策略；这不改变项目整体信任单人客户端的产品假设。

新增规则文件：

- `rules/npc-world.js`：居民、好友、成长、出征名单、持久化投影。
- `rules/npc-equipment.js`：完整配装比较、合法替换、唯一物品上限。
- `rules/group-loot.js`：资格、点数、需求/贪婪、超时与分配历史。
- `adventure-hall.tsx` / `adventure-hall.css`：大厅、档案与副本分装 UI。
