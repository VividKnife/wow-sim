# 战场：战歌峡谷

2026-09-22。主导航「战场」，主角20级开放。第一张地图是2D平面战歌峡谷，玩家指挥十人队伍对抗十人NPC队伍。世界阵营关系不变：银翼队、战歌队只是本场比赛分队，不依种族限制入场。

## 流程与规则

进入战场 → 不限时部署 → 10秒开门 → 实时夺旗与指挥 → 三旗胜负 → 统计及再次参赛。当前同级且存活的队友随主角参赛，其余位置由同级志愿队员补满。独立战斗状态不会修改冒险角色的血量、背包、装备、位置或阵营。

- 敌旗带回本方旗座且己方旗帜归位才能得分。全队阵亡不结束比赛。
- 持旗者死亡掉旗；附近队友可接力，原属队可触碰归还，10秒无人拾取自动归位。原属队在同一时间触碰掉旗时优先归还。
- 每30秒在各自墓地集体复活，满生命与法力，保留原指挥任务。短暂复活保护在攻击或拾旗后解除。
- 得分后10秒重置两面旗帜，先交旗三次获胜。无常规对局时间上限，可主动撤离判负。
- 双方连续持旗3分钟后，旗手受到的伤害每30秒提高10%，最高100%。这是本作主动加入的防僵局规则。
- 隧道疾速、北侧狂暴、南侧恢复增益每60秒刷新。疾速10秒提高50%移动速度；狂暴10秒提高30%伤害、10%受伤；恢复立即回复50%生命与法力。
- 记录单场击杀、阵亡、伤害、治疗、交旗及还旗，持久化参加场数、胜场和本队交旗数。本期没有荣誉货币、奖励商店或真人匹配。

10v10及三旗胜利参考暴雪官方的 [WoW Classic 战场介绍](https://news.blizzard.com/en-us/article/23237900/wow-classic-warsong-gulch-and-alterac-valley-now-live)。20级门槛、平面路线、比赛分队和防僵局机制按本项目需求设计，不声称逐版本复刻。

## 指挥模型

点击地图成员或名单进行多选，可以通过已有职责组、全选快速召集。每次命令包含成员列表、任务、路线；集合任务额外包含地点。命令即刻更新所选成员的任务、取消正在读的治疗，不等待下一回合；已走到一半的道路先走到端点再重新规划，禁止瞬移和穿墙。阵亡成员也可以接收命令。

| 任务 | 执行方式 |
| --- | --- |
| 夺旗 | 前往敌旗，取旗后返家；己旗丢失时退守己方高台。已有我方旗手时改为接应。 |
| 守家 | 守卫旗室，优先拦截附近敌方旗手，追击限制在本方基地附近。 |
| 护旗 | 动态跟随我方旗手；未取旗时接应夺旗手；附近治疗者优先治疗旗手与重伤成员。 |
| 追旗 | 动态追击敌方旗手，归还掉落的己旗；己旗安全时留在己方前场拦截。 |
| 中场 | 驻守中场，优先攻击射程内的敌方旗手。 |
| 集合 | 前往地图命名地点，支持组织进攻、回撤、高台防御和增益点控制。 |

路线有最短隧道、北侧坡道、南侧侧翼。命名地点及连通道路由权威模拟与渲染共享；路径使用带路线偏好的Dijkstra。基地墙体同时阻挡攻击与治疗视线。20名成员始终可见，属于本期指挥视角的简化，未实现战争迷雾。

持旗任务优先于个人命令，防止旗手因集合或追击放弃交旗；要调整护送路线，可向持旗者下达带新路线的任务。敌方每5秒重新分配攻守，依据双方旗帜状态增加追旗人员。玩家的任务不会被敌方AI或自动配阵覆盖。

## 技术边界

- `packages/game-data/battlegrounds.js`：地图、规则常量、任务文案、路线。
- `packages/game-domain/src/rules/battleground-space.js`：道路寻路、边段移动和视线。
- `packages/game-domain/src/rules/battleground.js`：独立比赛状态机、目标AI、职业职责战斗、旗帜、复活、增益、统计与命令验证。
- `apps/web/app/battleground.tsx`、`battleground.css`：React/SVG战术地图与DOM指挥面板。下拉选择统一使用GameSelect。
- `engine.js` 的100ms时钟推进对局；准备期冻结。`act`验证场次、命令版本、己方成员、任务与路线，并与其他活动互斥。
- `client-snapshot.ts`公开投影和Worker实时帧均包含战场。`useLocalBattleground`拒绝旧场次、旧时钟与旧命令版本；仍使用现有服务端持久化、本地租约、检查点与离线推进流程。
- 比赛保存为可序列化状态，无独立前端计时器。地图路径缓存仅由静态地图与输入决定，可丢弃再生成。

本期战斗是**职业职责简化模拟**，参赛者生命和法力来自现有角色属性，治疗有读条与耗蓝，近远程有射程，部分职业具备减速/昏迷及重复控制保护。伤害按生命与职责比例计算；不接入竞技场完整技能、装备触发、宠物、天赋及控制递减系统。该边界在界面规则说明中明确。核心体验优先覆盖夺旗决策、真实移动、遭遇战与动态人员调度。

## 验证

`node --test packages/game-domain/test/battleground.test.ts packages/game-domain/test/arena.test.ts`

覆盖等级门槛、不同种族、10v10唯一身份、准备/倒计时、活动互斥、批量命令与错误输入、地图路径/墙体/路线、己旗条件、三旗结算、掉旗/接力/归还/自动归位、复活波次、增益、防僵局、序列化与分段推进、伤害治疗、公开快照、领域服务保存及再次入场。

本地界面验证可运行 `node apps/web/scripts/serve-local-simulation-preview.mjs`，进入 `local-simulation.html?saveId=preview:arena`，选择「战场」。使用隔离的内存存档。

本次验证：12项战场测试与51项竞技场、本地模拟、快照和导航回归通过；领域及Web TypeScript检查通过，新战场界面ESLint通过。浏览器验证入场、分组选人、自定义路线、战中地图集合命令和持续推进，检查桌面与390px手机布局；页面没有原生select且无横向溢出。预览期间发现的规则版本不一致在重启隔离预览服务后消失，连续检查点与刷新接管另有领域测试覆盖。
