# HD-2D 战场

2026-09-20：战斗画面已接入 Three.js、React Three Fiber、Drei 和后处理。无需迁移 Godot。战斗规则、伤害结算和回放仍由原有权威状态驱动。

## 实现

- `apps/web/app/battle.tsx` 构造只读场景快照，保留队伍、职业面板、战斗记录、音效和策略交互。
- `app/battle-hd2d.tsx` 按需加载画布，处理 WebGL2 支持、加载、失败和恢复。恢复时清理相应纹理缓存并重新创建 lazy 组件。
- `app/battle-hd2d/frame.tsx` 提供共享帧与 160ms 坐标插值。相机、角色、血条、弹道和目标线使用同一坐标系。手动倍率作用于相机，不改变角色与布景的相对尺度。
- `environment.tsx` 提供草地、荒土、矿洞、甲板、浅滩五种场景，包含几何布景、光照、雾、阴影和环境粒子。
- `unit.tsx` 提供面向相机的透明精灵、移动/攻击/施法/受击动作、死亡倒伏、变形、图腾、脚底环、血条和飘字。可点击角色或队伍列表选择单位。
- `effects.tsx` 使用真实时间和范围绘制弹道、命中、治疗、持续区域、目标连线和房间边界。
- 精细模式启用阴影、Bloom 和景深；流畅模式固定 DPR 1、以 30 Hz 请求绘制、减少粒子并关闭后处理。隐藏页面停止画布帧循环；关闭窗口卸载画布。实际帧率取决于设备，未作跨设备性能保证。
- 系统减少动态效果设置会停用动作摆动、飘字动画与环境粒子。WebGL 不可用时继续保留下方状态、统计和战斗记录，并提供重试入口。

旧 Pixi 渲染器、SVG 战斗小人、相关依赖和废弃样式已移除。

## 素材与覆盖范围

本地运行时素材在 `apps/web/public/battle/hd2d/`：

| 文件 | 内容 | 大小 |
| --- | --- | --- |
| `characters.png` | 8 种角色/生物 × 6 个动作姿态，768 × 1024 RGBA | 588,227 B |
| `forms.png` | 熊、猫、羊 × 6 个动作姿态，768 × 384 RGBA | 220,165 B |

66 个动作格均经过透明边界和完整性检查，采用最近邻采样，脚底锚点统一为格内 `(64,112)`。六列分别是待机、两个行走步态、攻击、施法、受击；死亡由受击姿态结合倒伏与淡出呈现。

原创素材通过内置图像生成工具生成，并规范化分格。工具没有可选模型参数，因此不将其标记为特定的 `gpt-image-2.5` 输出。原始图片、预览、裁切元数据和完整提示词保存在同目录的 README 与 forms-README 中；页面仅加载运行时图集。

九职业按角色类型共享六种职业造型，其中圣骑士、术士、德鲁伊有配色变化；这不是逐种族、逐装备的外观系统。已有怪物优先保留项目中的全身透明模型图，使用位移、朝向、摆动、受击和倒伏等程序动作，尚非每种怪物独立绘制的多帧图集。熊、猫和变羊有独立像素动作图集。

五种已有地面材质继续使用 `public/battle/ground/`，其来源记录保持在原 README 中。

## 本地预览

在仓库根目录运行：

```powershell
node apps/web/scripts/serve-hd2d-preview.mjs
```

打开 `http://127.0.0.1:5178/hd2d.html`。预览使用内存中的真实战斗引擎，不连接账号或存档。关闭战斗窗口后可切换地面、重开五人战斗、开始单人战斗或暂停/继续模拟。战斗窗口保留缩放、选中角色和简化特效控件。

## 画面抖动修复（2026-09-20）

- 血条与时钟刷新不再向移动历史重复写入同一份坐标快照；新的权威坐标（包括停留原地的快照）仍正常记录。此前重复快照会把 100ms 的移动压缩到最后 1ms，造成先停顿再突跳。
- 相机位置与缩放统一由帧循环更新。页面滚动改变 Canvas 的 top/left 时，不再重新初始化镜头。
- 角色插值在 HTML 血条投影之前执行，且 React 更新不再直接覆盖角色位置，避免血条与角色使用不同帧坐标。
- 增加 4 项回归测试，其中 2 项使用 React Three Fiber 测试渲染器验证真实组件更新顺序与镜头行为；相关测试共 77 项通过，ESLint、TypeScript 和生产构建通过。
- 浏览器复查真实五人战斗、滚动及精细/流畅模式切换；静止战场滚动前后的角色投影变化小于 0.1 像素，控制台无错误。

## 战场比例修正（2026-09-20）

- 移除角色大小的固定世界单位下限。普通角色改为 2.8 码的风格化显示高度，精英 3.8 码、首领 5 码、巨人 4.5 码、宠物 2 码，与地面距离和技能半径使用同一转换。此前 90 × 48 码房间中普通角色的显示高度相当于约 14 码，超过 5 码近战距离。
- 自动取景使用以码为单位的边距和最小视野，避免场地变大时人物比例失真；1200 × 390 默认战场中的普通角色基准高度约 46 像素。手动缩放仍整体放大场景。
- 血条缩窄，名称、状态与技能提示独立定位，减少遮挡；角色动作幅度、弹道起止高度、命中和区域粒子同步按比例调整。
- 保留权威站位。真实五人模拟的远程起手距离约 26–30 码，怪物追到后排时也会出现实际近距离战斗，不以渲染偏移伪造间距。
- 新增不同场地大小、手动倍率下的尺度与取景回归测试；相关测试共 79 项通过，ESLint 和包含 TypeScript 检查的生产构建通过。浏览器检查远程施法与初始阵型，精细和流畅模式均正常，控制台无错误。
