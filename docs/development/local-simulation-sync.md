# 本地冒险启动、保存与任务操作

## 手机仍默认本地执行

手机与桌面均默认使用本地 Worker；不能仅凭触屏或设备类型把单账号战斗转到服务器。服务器资源有限，是否能持续实时计算必须测量规则推进、投影和消息复制，不能由脚本体积推断。曾添加的触屏自动服务端模式与 handoff 接口已撤回；现有多账号服务端战斗规则不变。

2026-09-28 对线上 Worker 的 GET 实测：未压缩 89,110,048 B，gzip 网络传输 11,968,396 B，此次桌面网络下载约 4.12 秒。约 89 MB 是解析前的脚本体积，不是已压缩传输量，也不是手机实时计算负荷。

同日 Apple M4 / Node v24.15.0 对当前源码的诊断：首次动态导入引擎与投影模块约 5.72 秒，导入前后 JS 堆使用量增加约 562 MB，进程 RSS 约 884 MB。没有强制 GC；这些是 Node 模块初始化过程的内存观测，不能视为手机浏览器稳态内存或设备上限。

固定种子 60325、3 级人类牧师、猎杀 299 号怪物；预热一次后重复三次，每次以 100 ms 步长推进 10 秒，其中 69 个 tick 开始时仍在战斗。纯规则推进分别 29.55 / 25.60 / 18.29 ms，规则 tick P95 为 0.80 / 0.90 / 0.69 ms；战斗投影加 structuredClone 后总计约 56–66 ms。一次完整总览另需约 98–112 ms。未包含真实 Worker 调度、主线程、GPU、网络或数据库，不能宣称真实手机已通过性能验收。

这些数据支持优先优化整包下载、全世界数据初始化与高频展示复制，而不是默认增加服务器计算。下一步应拆分当前活动所需数据、缓存静态内容，区分加载超时与运行无响应，并在真实 iPhone / Android 测量启动耗时、内存、持续落后量和指令响应。25 / 40 人团本须单独压测；已有桌面基准见 [团本优化记录](raid-capacity-optimization.md)。

页面同时监听 `pageshow` 和 `visibilitychange`，恢复浏览器页面缓存时重新检查执行状态。

## 状态与恢复

Worker 每次收到 `start` 后先验证内容版本并返回带会话 generation 的 `ready`，再开始结算、生成视图。启动确认不依赖页面是否可见。浏览器等待启动确认最多 15 秒；加载错误、消息反序列化错误、快照超时或即时操作超时会终止原 Worker，清除其展示状态，再从服务器已保存的进度启动新 Worker。原 Worker 的迟到消息不得影响新会话。

连续恢复最多两次；成功保存一个检查点后重置次数。超过次数明确停止并提示重新加载，不无限停留在“正在准备冒险”。规则版本或检查点结构错误仍停止执行并显示具体原因。自动恢复不能保留尚未保存的手动输入；未确认上传则必须先用原始 requestId 和原始请求体核对提交结果，再获取新会话。

后台只有一个排队或进行中的保存。战斗边界不在慢上传期间继续堆积保存请求。服务端错误、数据库忙、请求超时、会话冲突保留各自提示；Worker 超时走引擎恢复，不混成网络重试。

## 单次请求执行任务

Web 的普通游戏命令附带 `localCheckpoint`，不再先等待独立 `/api/game/local` 上传。服务器在同一个数据库事务中：

1. 校验角色、clientId、sessionId、内容版本和检查点序列；
2. 保存检查点并分配新物品的持久化 ID；
3. 重映射命令里的临时物品 ID，执行命令；
4. 写入命令回执并提交。

命令失败时检查点与命令一起回滚。命令回执包含检查点内容的哈希，相同 requestId 与相同请求可安全重放；不同内容不能复用回执。原检查点回执可用于核对丢失响应的结果。前端遇到不确定结果时保留检查点，核对后刷新权威状态，再恢复本地模拟，不重放用户命令。

角色切换仍先单独保存，因为它是读取另一个角色，不属于游戏命令事务。任务成功的响应立即成为页面状态；手动操作和结果核对期间不采用旧的本地快照覆盖服务器结果。后续重新接管 Worker 不阻塞任务结果显示。

## 响应体积与资料加载

物品 ID 只从装备、背包、奖励、材料等物品集合和明确的 item/itemId 字段收集。日志序号、任务 ID、怪物 ID、技能 ID 不应产生物品资料请求。

`view.dungeons` 仅包含入口资格、已保存进度等摘要；`view.dungeon` 仅在当前副本活动中携带完整地图和路线。静态手册和首领掉落仍通过已有内容包按需读取。

同一份 1 级人类术士状态的本地对照：完整快照从 1,342,552 B 降至 471,396 B（约 65%）；gzip 从 169,483 B 降至 62,457 B。此数值比较地下城摘要改动前后，不代表线上延迟实测；网络 RTT 与服务端负载仍会影响操作耗时。

- `apps/web/test/local-simulation-client.test.mjs`：启动确认、超时、更换 Worker、两次恢复上限、迟到消息隔离、上传结果不确定时恢复、保存合并、展示旧快照隔离、后台保存合并。
- `apps/web/test/local-simulation-worker.test.mjs`：隐藏页面启动、分片结算、暂停检查点、会话隔离。
- `packages/game-domain/test/local-command.test.ts`：事务原子性、重复请求、临时物品 ID、角色与会话隔离。
- `apps/game-server/test/server.test.ts`：大检查点与命令共用一个鉴权请求、重放和输入校验。
- `apps/web/test/content-packs.test.mjs`、`dungeon-journal-content.test.mjs`、`dungeon-view.test.mjs`：物品资料范围、入口摘要预算和活动副本功能。

Web 与 game-api 必须一起发布；本协议不保留旧服务端的双版本兼容路径。Worker 规则变化需重新运行 `npm run data:compile` 并刷新页面加载同版本规则。
