# PvP 竞技场设计草案

日期：2026-09-22。状态：首版 NPC 竞技场已实现；下文保留完整设计目标，实际范围与限制见 [竞技场实现与验证](../development/arena.md)。用户已确认：准备不限时；当前对手全部为 NPC；战斗引擎必须接入魔兽世界拟真的 PvP 技能、计算与限制。首版同时开放 2v2 / 3v3 / 5v5，默认选择 3v3。未在实现文档确认的赛制参数仍为建议。

## 1. 核心方向

让玩家通过阵容、赛前情报、团队战术和地形使用赢得自动战斗。每场应能回答三个问题：我想怎么赢、队员是否执行了计划、下一场应该改什么。

推荐主模式为 **3v3**，**2v2** 用于入门和战术练习，**5v5** 在协同 AI 与战报可读性成熟后开放。底层按可配置人数实现，当前不建设真人排位。

当前范围：一名玩家带自己的伙伴组成小队，对战 NPC 竞技队；赛前不限时编排战术，点击开始后自动战斗。真人匹配、玩家阵容发布、异步防守与跨账号积分均不属于当前开发范围，也不是首期的前置工作。

版本沿用项目的 [2019 Classic Phase 1 / 1.12 参考基准](version-baseline.md)。竞技场赛制、原创地图与自动指挥是产品改编；技能效果、伤害治疗、控制、解控和施法合法性以该版本的 PvP 行为为准。不能拼接 TBC、巫妖王、正式服或其他 Classic 分支的规则，也不因对手由 AI 操控而使用怪物战斗公式。

### 拟真是引擎接入的验收要求

必须区分三个独立概念：`controller`（用户策略或 NPC AI）、`combatantKind`（玩家角色、宠物、图腾等）和 `ruleset`（当前版本的 PvP/PvE 规则）。NPC 竞技选手是由 AI 操作的玩家角色，必须享有并受到同样的属性、技能、目标限制与 PvP 控制规则约束；宠物和图腾仍保持各自的单位规则。

伤害、治疗、资源、效果与光环继续进入共用战斗内核。补充版本化的 PvP 目标判定和规则数据，不复制一套简化技能执行器，也不能只给 PvE 伤害乘一个统一系数就视为完成接入。

| 引擎领域 | 必须接入或逐项核验的内容 |
| --- | --- |
| 角色与目标类型 | 等级、种族、职业、合法天赋、形态、武器/护甲、技能等级、资源、阵营关系；角色、宠物、图腾和受控单位分别判定；不能依赖是否有真人账号判断 PvP 身份 |
| 物理攻击 | 玩家目标攻击表、白字/技能区别、双持、命中、暴击、闪避、招架、格挡、武器技能/防御影响和正背面判定；确认偏斜、碾压等机制的适用对象，禁止直接套用首领/怪物攻击表 |
| 法术与治疗 | 玩家目标法术命中与抗性、二元/非二元法术、伤害/治疗系数、暴击、持续效果、减疗、吸收、减伤、伤害转移及结算顺序；无证据不新增全局 PvP 伤害或治疗倍率 |
| 控制 | 每个技能的 PvP 时长上限、递减组与例外、共享关系、衰减阶段、重置计时、提前结束/抵抗；区分主动与触发控制，不能按控制名称猜分组 |
| 打断与施法 | 读条、引导、沉默、学派锁定、打断抵抗、施法受击推迟、公共/技能/类别冷却；锁定一个学派不等于禁用全部技能 |
| 解除与免疫 | 驱散类别、方向、可驱散标记、数量、抵抗；伤害破控条件、免疫覆盖、种族/职业解控和实际版本的 PvP 饰品；不能给所有人额外赠送万能解控 |
| 职业限制 | 潜行/战斗状态、连击点及目标切换、能量/怒气/法力、姿态/形态、装备/盾牌、近战距离/远程盲区、背后要求、目标生物类型；技能不满足条件就不能执行 |
| 空间 | 技能的距离、朝向与视线检查时点、弹道发出后的行为、范围/链式效果、冲锋/闪现的路径及落点；地图碰撞与技能语义分别验证 |
| 持续战斗 | 脱战与重新潜行、法力恢复、食物饮水/绷带/消耗品条件、宠物控制和重召；比赛暂停准备不等于获得战斗中的无限回复 |
| 时序 | 同时施法、控制和打断的处理顺序；现有 100ms 模拟 tick 不自动等于历史服务端法术批处理，需独立校准并声明拟真边界 |

每项具体规则记录版本、技能/效果 ID、目标类型、公式或状态转换、证据、验证状态与测试用例。优先使用对应版本官方说明和可复核战斗记录；固定提交的社区核心只作为参考，不能当作官方真值。未知项明确标记，不以技能表存在、单元测试通过或 NPC 对局胜率正常代替原版一致性证据。

首批端到端场景围绕压治疗、保治疗和控 A 打 B：变形术及形态/生物类型限制、恐惧与破控、定身与移动、晕眩与递减、脚踢/反制/震击的学派限制、驱散与净化、减疗与吸收、潜行/消失/脱战、种族/饰品解控，以及宠物/图腾参与。只有实际等级可用且完成场景验证的技能才进入首期 NPC 战术模板。

变形、恐惧、晕眩、定身、沉默和缴械不能共用一个「无法行动」开关；每种状态分别决定移动、施法、武器攻击和物品使用权限，具体例外取自版本数据。

## 2. 人数选择

| 模式 | 适合的体验 | 主要设计风险 | 推荐定位 |
| --- | --- | --- | --- |
| 2v2 | 一眼看清每个人的职责；学习打断、保护、绕柱；阵容成本低 | 一个控制或职业短板影响过大；治疗组合可能拖长比赛 | 练习、切磋；首期不另设独立排位 |
| 3v3 | 压制、控场、治疗能分工；换火与救援有取舍；容易复盘 | 双输出加治疗可能成为主流，需要验证其他组合是否有合理空间 | 主模式与优先平衡对象 |
| 5v5 | 使用现有完整五人队；分组压制、多人接控和大规模转火 | 瞬间集火过强、控制分配复杂、画面难读、调参面大 | 后续开放，先做活动或非排位 |

不强制「坦克/治疗/输出」配额，也不强制带治疗；默认推荐 3v3 的双输出加治疗。三输出可以用控制换取击杀窗口，但要承担续航不足。五人 PvE 队不能原样套用仇恨职责，坦克型角色在竞技场要靠减速、打断和保护产生价值。

玩家主角占一个出战位，其余从现有伙伴中选择。选择出战席位不等于解雇伙伴；2v2、3v3 不应收取伙伴更换费。首期不另外开放同一成员的克隆副本或不限量竞技专用伙伴。

## 3. 参与方式与公平边界

### 首期：NPC 竞技巡回赛

- 对手有固定职业构成和可解释的战术模板，包括压治疗、保后排、控场爆发等；难度靠策略与配合调整，不能暗中提高反应速度、看穿潜行或忽略视线。
- 清楚标注 NPC 训练队，不假装成在线真人。此模式能独立验证竞技场体验，不依赖玩家数量。
- 对手阵容、地图与随机种子在比赛创建时固定；刷新、断线不能重抽对手或重掷结果。

### NPC 阵容规则

- NPC 使用合法的职业角色模板、装备、天赋与已学技能；等级和装备档位明示，不能使用首领免控、怪物生命倍率或隐藏资源加成。
- NPC 队伍与己方都经过同一策略调度、技能合法性检查和效果结算流程；双方都需要处理递减、学派锁定、施法距离、视线和宠物状态。
- NPC 按可感知信息执行战术，不能读取玩家未展示的策略或随机结果；难度来自阵容和策略选择。
- 训练允许重打与固定种子复盘，NPC 挑战进度独立记录；暂不设计真人匹配或跨账号升降分。

### 竞技整备

- 训练赛使用当前等级、实际已学且已实现的技能和真实装备，标明训练档位。不能为低等级阵容虚构缺失的核心技能。
- 可另提供明确标记的统一装备练习模板，保留职业、种族、合法天赋选择和策略差异；不默认把真实装备养成全部替换。NPC 使用同档位的合法属性与物品。
- 在相应等级的技能、宠物与天赋机制验证完成前，不开放依赖该档位的正式挑战。先验证当前可玩等级，不直接假设完整满级机制已经可用。
- 所有整备操作只作用于比赛副本，不回写 PvE 等级、装备或背包。材料、弹药、资源和消耗品在比赛内仍按合法规则消耗；不扣真实背包不意味着施法条件免费。

## 4. 单场流程

流程：选择模式与阵容 → 分配对手和地图 → 情报与准备 → 锁定 → 3 秒开门倒计时 → 自动战斗 → 结算与复盘。

### 准备阶段

**准备阶段不限时，不存在准备超时、自动锁定或自动开战。** 玩家可以持续查看阵容、地图和调整策略；仅点击「开始战斗」且配置通过校验后，才进入锁定与开门倒计时。开门 3 秒只是玩家主动开始后的演出，不是准备期限。

准备阶段冻结比赛模拟时钟，不推进伤害、资源回复、光环、技能冷却、NPC 决策或随机数。草稿保存并可刷新恢复；离开界面不会自动开战。允许取消准备且不判负。持久化或服务资源回收不能被用作隐含准备时限。

准备时展示：

- 双方职业、公开专精/定位、宠物类型、装备规则；敌方用稳定编号 A/B/C 区分同职业成员。
- 地图、出生区、柱体轮廓与视线规则。
- 己方战术摘要、控制接力顺序、爆发条件、保护对象与开局站位。

隐藏对手的具体战术、技能优先级、控制链顺序与随机状态。阵容情报不意味着战斗中能够持续看见潜行单位的位置。

看见对手后允许调整目标标记、团队战术、个人规则、初始站位；本场出战成员、职业、天赋和装备以创建时快照为准。需要修改阵容可取消准备后重新进入；NPC 对手和地图按本次挑战固定，不通过刷新或取消重抽。比赛规则或地图版本在创建时一起冻结。

倒计时结束前全员不能移动、攻击或对敌施法。合法己方增益和宠物在锁定后的整备步骤统一建立，需检查实际技能、材料、宠物选择和互斥关系。双方生命、法力与冷却状态按明示的比赛整备规则初始化；这是赛制设定，不宣称为原版竞技场规则。具体资源初值按职业定义，例如怒气与连击点不默认满值。准备冻结不会积攒资源或让短期增益无限延期进入战斗。

编辑器区分「已保存」与「未提交」。点击开始时，保存并校验当前草稿、锁定版本、创建战斗状态应原子完成；校验失败留在准备页并指明原因，不开始倒计时。未设置自定义战术时使用可见的合法推荐模板。明显冲突必须在保存时处理，不能等开门后临时静默改写。

### 胜负与结束

- 单局制；一方所有出战角色死亡即失败，宠物与图腾不能单独维持比赛，不开放战斗复活。
- 同一结算时刻发生的伤害、死亡与胜负检查按明确阶段处理；双方同时失去最后角色判平局，不能由数组遍历顺序决定胜负。
- 观察战斗时长，不为强制达到 1–3 分钟而修改原版技能。不开启自定义的自动治疗/吸收衰减或无交互后的全员显形。
- 战斗时长上限与准备阶段无关。实现初期可用明示的最长战斗时间结束异常长局，暂建议 10 分钟，超时平局；这是待测赛制规则，不改变技能效果。不按累计伤害判胜，不因长时间潜行让 AI 透视。永久不接敌先排查 AI/寻路，合法长局按赛制正常结束。
- 断线后按已锁定策略继续；重连恢复比赛进度。投降直接判负，不能通过退出规避结果。比赛故障作废并单独标记，不当作平局用于积分。
- 比赛死亡不产生跑尸、耐久损失或真实消耗品扣除；结束后销毁竞技临时状态，不覆盖 PvE 状态。

## 5. 战术系统：团队计划指挥个人技能

现有个人技能优先级继续负责「用什么技能」。增加团队层负责「对谁、为什么、何时配合」；不要要求玩家为每个成员重复编写完整团队状态机。

### 战术界面

左侧己方成员，中间地图与站位，右侧敌方编号和职责；下方是按优先级排列的战术卡片。

每张卡片包含：执行成员、任务、目标、触发条件、结束条件、追击限制、失败后的退路。新手从模板开始，进阶玩家再展开条件与顺序。

首期任务：

| 任务 | 玩家语义 | 执行约束 |
| --- | --- | --- |
| 压制 | 盗贼持续干扰敌方治疗 | 持续攻击并优先打断指定施法；不跨越追击边界送死 |
| 保护 | 法师保护己方治疗 | 识别实际威胁，用减速、控制、打断争取治疗空间 |
| 控制 | 保持 A 的控制窗口 | 多名成员依次接力，按递减与免疫选择技能，避免误伤 |
| 集火 | 主要输出攻击 B | 对齐目标与爆发条件，不能强制越过施法合法性 |
| 转火 | B 无敌或无法接近时改打 C | 有持续时间与恢复条件，避免每个 tick 反复换目标 |
| 撤退 | 治疗受压时回到支援区 | 限定锚点和路径，仍遵守速度、定身、视线和地图 |

目标选择支持：指定编号、敌方主要治疗、正在攻击指定友方的敌人、当前集火目标、指定友方。动态目标用固定排序与短暂锁定选出一名；默认不包含宠物，显式任务可选宠物。

自然语言可以作为未来的战术输入方式，但执行源必须是可检查的结构化卡片；不依赖模型在每个模拟 tick 解释文本。首期通过预设和表单即可完成全部核心玩法。

### 三个具体示例

**压治疗：**「盗贼压制敌方治疗 A；治疗法术读条时优先脚踢；A 绕柱后可短距离跟随，但与己方治疗失去视线超过 2 秒，或己方生命低于 35% 且无法获得治疗时回撤；重新获得支援后继续压制。」

**输出兼保护：**「法师默认输出 B；己方治疗被近战贴身或遭连续集火时，优先对主要威胁减速/控制并打断危险施法；治疗脱险后恢复输出 B。」保护触发不能只等治疗低血，脱险采用比触发更宽的距离/血量条件并保持约 2 秒，避免职责抖动。

**控 A 打 B：**「法师先控制 A，第二控制手接续，其他人集中攻击 B；A 的控制实际生效且至少两名输出可攻击 B 时开启爆发。接控失败时按计划继续施压或暂缓爆发。」3v3 双输出加治疗只有两个主要输出位；三输出协作可以用于 3v3 无治疗阵容，或用于带治疗的 5v5。

### 决策优先级

先过滤死亡、控制、资源、技能、射程、视线等硬限制，再在合法行为中选择：

1. 已配置的紧急保命/救援。
2. 影响当下战术的紧急打断和保护。
3. 即将到期的控制接力或约定爆发动作。
4. 长期任务：压制、普通输出、常规治疗。
5. 为任务寻找合法位置或按退路回撤。

保护、控制和集火冲突时必须有唯一决定，并在战报说明。紧急救援可让控制链中断；不会为了保持一条控制链让己方治疗必死。卡片允许调整策略偏好，但不能越过技能合法性，也不能把 GCD、资源和冷却当作免费动作。

默认不随每次任务重新选择中断正在进行的施法；只有明确的紧急规则能取消，取消按共用施法规则处理。

## 6. 控制链、打断协同与爆发窗口

控制链是「协调合法施法」，不是保证敌人永久无法行动。

- 技能配置控制类别、受伤是否解除、递减组、免疫限制、解控方式和预计持续时间。
- 按目标与版本定义的递减组维护共享状态，换施法者不能自行重置；具体技能是否递减、是否共享、倍率、持续上限及重置周期逐项核验。禁止凭经验写死统一重置时间，或把其他版本的分组直接套入。
- 到期、驱散、解控、伤害打破、提前抵抗、免疫和重复施加都要有明确的递减状态转换；失败是否更新状态以具体版本证据为准。不同控制组独立；打断的学派锁定与硬控制分开定义。
- 控制协调器为「目标 + 控制链步骤」分配短期预约。下一位提前考虑读条和弹道时间，只有前一控制确认生效/结束后才推进；同一目标的同类预约不能重复发出。
- 被打断、沉默、死亡、失去视线、技能不可用或目标免疫时立即释放预约，按备援顺序尝试；无合法接手者时接受控制空窗。
- 打断另按「目标 + 本次施法实例」预约，避免两人同时浪费打断。即时解控、驱散和免疫也会触发重新决策。
- 待控制目标默认进入「保护控场」名单，直伤、自动攻击、宠物、攻击图腾、顺劈和范围技能都要检查；打断目标治疗时也不能误打醒已受控目标。
- 已存在的持续伤害或已飞出的弹道不能撤销。编排时提醒可能破控；执行时选择不怕伤害的控制，或等危险效果结束。不能靠策略层删除 DoT 来保证控制成功。
- 控场对象和集火对象相同时，编辑器要求明确采用「伤害不解除的控制配合集火」或修改目标；不能默默禁用全队攻击。
- 默认爆发最多等待约 4 秒；条件一直不能成立时按卡片选择继续常规输出或换控制对象，避免全队无限等一个窗口。
- 「持续输出」不意味着所有进攻冷却一好就交。常规技能保持压力，爆发技能组可留给控制成功、敌方大减伤结束或队友就位后的窗口。

解控能力只来自目标版本实际存在且角色合法拥有的技能、种族能力或物品。逐项校验解除类别、使用条件、冷却和共享冷却，不额外赠送统一竞技解控技能。

## 7. 地图、柱体与施法视线

首期采用固定、对称的平面竞技场；表现可使用现有 HD-2D 场景，权威空间规则仍是二维。首张图先做双柱，第二张四柱验证换边和接力，第三张留作后续变体。

| 地图提案 | 布局 | 想验证的策略 |
| --- | --- | --- |
| 双柱庭院 | 约 48×36 码；对称双柱、中央交战带 | 最容易看懂的断视线、追击限制与保护 |
| 四柱角斗场 | 约 56×44 码；四根错位对称柱 | 治疗换柱、输出侧绕、截断追击路线 |
| 断墙遗迹 | 约 52×40 码；两段短墙与侧通道 | 控制通道、换火与多方向支援 |

尺寸为关卡设计初值。所有出生区至少连通两条进入交战区的路径，不能有不可达口袋、单向必胜点或无法结束的绕柱路径。第一版不加入升降柱、随机火墙、落差与跳台，避免把空间问题和时序机关叠在一起。

### 柱体不是装饰

- 障碍数据至少区分阻挡移动与阻挡视线；柱体和实墙默认两者都阻挡。用统一的圆/多边形碰撞定义驱动模拟、地图预览和场景模型轮廓。
- 寻路必须考虑角色碰撞半径；线段步进与碰撞一起判定，不能只检查终点，防止高速移动穿柱。
- 普通追击、撤退、恐惧、宠物寻路均遵守可通行空间；冲锋和闪现分别核验路径/落点规则，不用普通步行碰撞规则替代移动技能语义。不能仅凭技能名称决定能否越过间隙、绕障或截停。
- 不以 Three.js 相机射线或模型是否透明决定法术命中；镜头遮挡与战斗视线是两个概念。选中单位被布景遮住时可淡化模型，但其柱体碰撞仍有效。

### 法术检查时点

以下是必须建立的验证项目，不是已完成验证的原版行为表。核验后将规则写入技能/效果数据；没有证据的条目不能通过统一默认值悄悄变成正式规则。

| 行为 | 必须确定的检查与例外 |
| --- | --- |
| 指向性伤害、治疗、控制、打断 | 施法开始、提交、命中分别是否检查距离/视线；瞬发、读条和特殊技能分别建立契约 |
| 读条中途断视线 | 中途或完成时的失败判定、消耗与冷却处理；AI 主动取消与规则取消分开 |
| 引导 | 开始、每跳及目标脱离视线时的检查；不能统一假定全部引导立刻中止 |
| 已发射弹道 | 施放后是否跟踪、是否重新检查视线、哪些效果有障碍碰撞；不采用「所有弹道撞柱消失」的自定义规则 |
| 已附着的持续伤害/治疗 | 持续效果与重新施加的区别，是否存在特殊距离/视线条件，不因渲染遮挡自行删除光环 |
| 地面/自身范围技能 | 施法点合法性、效果中心、逐目标遮挡及技能例外；不一概认定所有 AoE 都按单体视线规则执行 |
| 链式技能 | 首个目标与每一跳的距离、视线、目标资格及衰减 |
| 普通近战、远程攻击 | 距离、朝向、攻击范围/体型与地图遮挡；投射表现不能反向决定命中 |

柱体必须实际影响需要视线的攻击和治疗；绕柱也可能切断己方治疗。具体检查时点和例外遵守技能契约，不能为让某张地图或战术更强而任意改写。

### 走位 AI

角色寻找「能够完成当前任务的可达位置」，而非一直朝目标中心直线移动。

- 治疗优先兼顾友方治疗视线、敌方压力和回撤路径；需要时从柱后探出，不永远藏在无法治疗的位置。
- 远程优先侧移取得射线；不能为修复视线无条件走进近战。
- 近战评估绕柱路径长度与治疗支援。追击目标使用暂时不可见的最后位置记忆，记忆超时后重新搜索，不能获得潜行目标真实位置。
- 保护者移向被保护成员和主要威胁之间可施法的位置；靠技能控制创造空间，不声称仅用模型站位就一定挡住敌人。
- 位置候选评估兼顾路径长度、任务视线、己方治疗视线、敌方压力和追击上限；设置目标锁定/重规划节流，防止来回横跳。
- 双方使用相同的可感知信息与反应延迟。建议战术层每 200 毫秒决策，物理和效果继续沿用 100 毫秒模拟步长；反应与接控参数通过实测调整，不追求毫秒级完美接控。

## 8. 战斗观看与复盘

战斗界面要能读懂战术正在做什么：

- 明确标记集火 B、控制 A、被保护成员；目标线按需显示，5v5 不能默认把所有连线铺满画面。
- 控制目标显示当前状态、递减和下一接手人；成员显示简短意图，例如「保护治疗」「绕柱寻找视线」「等待爆发」。
- 用短提示解释计划变化：「A 被解控，法师补控」「B 隔柱，暂转 C」「治疗遇险，取消追击」。
- 普通玩家先看胜负、关键转折和三条主要原因；高级详情再看完整事件流。

复盘至少包括控制有效时长、控制重叠/空窗、误破控制、打断目标及被打断技能、集火一致性、支援距离、视线阻挡次数、成功/失败的保护行动。

关键事件必须来自模拟日志，不把推测包装成事实。例如可报告「死亡前 2.4 秒治疗被柱体遮挡」，不能据此无条件断言「只要不绕柱就能赢」。

训练赛支持复制配置后重打，固定种子用于比较改动；有进度/奖励的 NPC 挑战不能改过去的策略重结算。战斗中不编辑比赛策略；暂停、慢放、快进只改变已经生成的回放展示。

前端选项使用项目统一 `GameSelect`，带图标的复杂选项使用现有 Radix Select；不使用 `<select>`、`<option>` 或 NativeSelect。键盘、标签、禁用状态与窄屏编辑必须保留。

审阅时，空间层明确只处理矩形边界；若干技能筛选依赖 `combat.enemies`，敌方目标选择依赖仇恨。没有据此宣称 PvP 是给怪物换一个玩家外观即可完成。

### 建议的领域边界

- `ArenaMatch`：模式、队伍快照、地图版本、规则版本、准备草稿、主动开始/锁定时刻、阶段、结果与结算状态；不包含准备截止时间或自动开始计时器。
- `CombatTeam` / `Combatant`：比赛内唯一 ID、队伍 ID、控制器、单位战斗类型、原成员引用、宠物归属和生命周期。即使双方都引用同一个模板，实体 ID 也不得碰撞。
- `TeamTactics`：版本、默认目标、职责卡片、控制链、爆发条件和回退规则。
- `TacticalRuntime`：当前意图、预约、感知记忆、递减、目标锁定和重规划时刻；完整参与确定性快照。
- `ArenaMap`：边界、出生区、障碍形状、碰撞/视线标记、表现资源引用。
- `ArenaRuleSet`：人数、等级/装备规则、整备、所引用的 PvP 规则版本、战斗时间上限与获胜条件。控制和技能数据由战斗规则版本提供，不作为关卡难度参数任意修改。

统一提供相对某个行动者的友方/敌方查询与技能合法性检查，覆盖伤害、治疗、驱散、宠物、图腾、范围技能与控制后的关系变化。双方使用相同技能与效果执行器；AI 决策策略可因玩法不同而替换，不复制另一份「PvP 伤害公式」。

对当前结构可以直接重构并同步更新调用方、脚本、测试与文档；不新增旧存档兼容、迁移或双格式逻辑。

### 执行权与结算

当前仅有玩家对 NPC，不因玩法名为 PvP 就引入真人竞技的匹配、防作弊和双边积分基础设施。是否本地运行与是否使用 PvP 战斗规则是两个独立维度。

- 复用现有单账号本地模拟/服务器回放的执行架构及其信任边界；两种执行位置必须使用同一 PvP 内核和规则版本。若 NPC 挑战以后增加需要服务器权威的奖励，再显式指定执行策略。
- 当前不宣称已有反作弊能力；不为未来可能的跨账号对战预先建设提交禁令。未来新增真人竞技时重新定义权威执行与结算，不能未经验证直接沿用可信客户端结果。
- 阵容、地图、战术版本、规则版本和随机状态在开战时锁定；技能及战术变更不能影响进行中的比赛。
- 创建、保存准备、取消准备、开始、投降、最终结算各有状态校验与幂等键；按比赛 ID 唯一结算 NPC 挑战进度和奖励，重试不得重复发奖。
- NPC 比赛锁定后可沿现有架构推进或预计算；刷新不得重抽随机状态。前端展示与 AI 感知不暴露当前不可见目标位置；完整模拟检查点和可感知投影不能混为一谈。
- 断线或 Worker 挂起按现有检查点恢复，恢复后执行锁定策略；不承诺浏览器关闭后本地模拟仍持续运行。准备态恢复仍停在准备态，不能走战斗离线补算。

## 10. 开发顺序与验收

### 阶段 A：验证战斗内核

先建立版本化 PvP 规则契约与证据清单，再完成对称职业执行、玩家目标攻击/法术结算、职业限制、控制/解控、竞技整备与胜负结算。先用无柱测试场验证两队确实遵守同一规则；测试场不作为正式地图上线。未完成的机制必须显式阻止依赖它的技能/模板进入正式挑战，不允许静默回退为怪物规则。

### 阶段 B：做出完整的 3v3 训练玩法

一张双柱地图、不限时准备界面、四类核心战术（压制、保护、控场、集火）、预约与回退、经核验的视线/寻路、NPC 对手、关键事件复盘。必须实际复现用户提出的三类策略，才能称为首个可玩版本。

### 阶段 C：扩充玩法并验证数值

第二张四柱地图、2v2 练习、更多合法 NPC 阵容和挑战档位。完成对应等级的 PvP 技能契约与端到端验证后再扩大阵容；挑战积分如需加入，仅表示 NPC 挑战进度，不是真人排位。奖励另行确定。

### 阶段 D：验证 5v5

加入分组集火、三人控制接力、更多保护职责与队伍级信息过滤；验证十个角色加宠物/图腾的 CPU、回放体积与手机画面。对手继续全部为 NPC。

### 必须通过的行为验收

1. 盗贼能持续压治疗、合法打断；失去支援或目标不可达时按规则回退。
2. 法师会从输出切换保护己方治疗，危险解除后恢复任务，切换不抖动。
3. 多人控制链不重复预约；递减、抵抗、免疫、驱散、伤害破控和备用接手都正确。
4. 既有 DoT/弹道能真实破控，宠物和群攻不会无视控场保护。
5. 目标绕柱后，伤害/治疗读条、瞬发、引导、链式技能与已发出弹道分别遵守有版本依据的视线契约；不能用统一「碰柱销毁」实现通过测试。
6. 近战、宠物、恐惧遵守可通行空间，冲锋/闪现按各自契约验证；不可达时及时换任务，不无限撞墙或原地发呆。
7. 阵营与出生点交换后，镜像测试不会因处理顺序获得固定优势；同一时刻双灭可判平。
8. 相同输入、种子与版本的重复模拟、分段推进、保存恢复结果一致，包含全部 AI 协调状态。
9. 准备任意长时间、保存/刷新/离开恢复、取消准备、主动开始、校验失败、重复开始、断线、投降和重复结算均有测试；准备态不推进模拟，不积攒资源，不自动开局。
10. 双治疗、全输出、长时间潜行和无人接敌能按规则结束；低等级缺技能时界面不提供非法战术步骤。
11. 同一职业角色改由 NPC AI 操作不改变命中表、控制上限、递减或技能条件；宠物/图腾不因属于 NPC 队而使用错误单位类型。
12. 每个开放技能有 PvP 合法/非法目标、命中/抵抗/免疫、资源/冷却、作用时长和关键天赋的场景测试；预期值来自独立数据或证据，不直接复制被测公式。
13. 职业交互至少验证形态与变羊、学派锁定与其他学派施法、正背面与防御结果、驱散与毒/诅咒/魔法分类、实际可用解控与不能解除的控制；具体结果按版本契约断言。

### 平衡观察与放行标准

记录阵容/专精/地图的胜率与样本量、比赛时长分布、开局快速死亡比例、控制重叠和空窗、超时比例、寻路停滞与反复取消施法。NPC 胜率不能证明技能与原版一致，也不能单独证明玩家策略已平衡。

采用固定种子回归集加独立随机种子样本，对称出生位成对测试；先排查版本/公式错误、AI 和地形问题。职业克制或合法控制循环不能仅因胜率偏高而被改成自定义机制；难度优先通过明示的阵容、装备档位与策略调整。放行要求没有违反技能契约的穿障、控制、透视、无限资源或不可达卡死，所有公开阵容的核心交互具备测试与证据；具体性能和时长门槛由基线确定。

## 11. 已确认与仍待验证的边界

已确认：准备不限时、当前全部 NPC 对手、魔兽拟真 PvP 内核与技能限制。没有准备期限、没有当前真人排位、没有统一赠送解控。控制递减和技能时长属于版本核验工作，不是随意选择的产品平衡参数。

仍待产品细化：人数开放顺序、NPC 挑战档位与奖励、是否额外提供统一装备练习、最长战斗时长。无需为这些细节重复确认已确定的准备方式和 NPC 范围。

仍待工程核验：逐技能 PvP 时长与递减、物理/法术公式分支、空间检查时点和历史批处理语义。已有技能执行器提供基础，但不代表这些机制已经接入或获得原版一致性验证。
