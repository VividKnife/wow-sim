# 魔兽风格 UI 第二版：玩法、规则与验收

## 版本保留与范围

- V1 继续使用 `/classic-ui.html`；本轮不修改其 HTML、TSX、CSS。
- 开始前的源码、共享场景组件和背景已归档到 `classic-ui-v1-2026-09-23.tar.gz`，SHA-256：`052801c9e9746757e33a9cc8a34dba8c2235fed5605a9c198c16c1852cb8469b`。
- V2 独立入口 `/journey-ui.html`。先实现世界任务循环和所需人物、任务、角色、小队、战报窗口；不重写正式游戏入口，不假装其他页面已设计完成。
- 独立临时角色与正式存档隔离。20 级五人队伍、已完成北郡介绍任务、有旅行棕马，是明确的试玩初始条件；之后所有任务、旅行、战斗、拾取、经验与奖励经现有引擎结算。

## 已读取的玩法来源

`apps/web/app/game.tsx`：页面入口、网络/命令错误、角色选择、后台模拟与战斗切换。
`world.tsx`、`local-npcs.tsx`、`journey-activity.tsx`：导航与交互限制、NPC 服务、任务接受/奖励选择/交付、停止语义。
`character.tsx`、`party.tsx`、`dungeon-page.tsx`、`raid-page.tsx`、`pvp.tsx`、`journey-log.tsx`：成长与远征入口。
`packages/game-domain/src/rules/engine.js`、`quests.js`：权威操作、目标计数与结算。
`world-scene.worker.ts`、`world-camera.js`：Worker 模拟与人物取景。

核心循环：查看当前状态与委托 → 选择目标/风险 → 接任务 → 导航（自动召唤已拥有且可用的坐骑） → 抵达后开始自动狩猎 → 观察战斗/恢复/停止 → 完成目标自动停止 → 返回委托人 → 交付奖励 → 配装、训练与下一段旅程。
玩家主要决定目标、路线、阵容、成长与自动战斗策略，不是逐个手动施放技能。

## 主要页面的决策与操作矩阵

| 页面/功能 | 玩家决定 | 必需信息 | 主要操作 | 结果/限制 |
|---|---|---|---|---|
| 世界/旅行 | 去哪里、做什么、是否中止狩猎 | 位置、目的地/剩余时间、血蓝、当前活动、任务目标 | 导航、狩猎、采集、改变目的地 | 旅行完成才更新所在地；战中停止是本场结束后停止；地面旅行不可直接 stop |
| 附近人物 | 与谁交谈、使用哪项服务 | NPC 身份、可接/可交任务、服务类型 | 接受、交付、训练、交易、旅店/飞行 | 必须抵达并满足交互状态；不按阵营禁止城市服务 |
| 任务 | 优先完成哪项、奖励选哪件 | 目标数量、来源区域、等级、奖励、可交付地点 | 接取、导航、完成/选奖、放弃 | 收集/击杀/事件不是同一种操作；某些剧情为已有适配脚本 |
| 角色/背包 | 换哪件装备、如何处理物品 | 装备槽位、属性、物品品质、背包容量、使用条件 | 装备、使用、整理 | 结果应更新真实属性；不足/限制明确反馈 |
| 法术/天赋/策略 | 学什么、投入哪里、自动施法优先级 | 已学等级、费用、前置、未实现标记、规则条件 | 训练、加点、调整规则 | 不把参考数据中未实现技能当作已支持 |
| 坐骑/旅行技能 | 是否骑乘、使用何种交通 | 已拥有/骑术/等级、召唤进度、当前位置限制 | 召唤、下马、飞行、炉石 | 已有真实召唤与航程；换装/坐骑首次加载有等待 |
| 生活职业/银行/市场 | 生产采集、存取交易 | 技能/配方、材料、容量、价格、活动状态 | 生产、采集、存取、交易 | 账号后台活动与当前角色活动不同；本轮不改造 |
| 小队 | 职业职责如何搭配、替换谁 | 人数、职责、血蓝、等级、招募/替换条件 | 招募、更换、配置 | 10级开放，五人上限；新招募与付费替换区分 |
| 地下城 | 选哪座、是否准备好、走哪条路线 | 开放/最低等级、阵容、入口、首领/掉落、补给 | 查阅、前往、进入、推进/暂停 | 手册可查不等于副本可玩；本轮只整理规则 |
| 团本 | 金团、阵容与战术 | 60级、25人、首领进度、机制、分配规则 | 招募、开始、调整战术/竞拍 | 使用持久冒险者名单与统一分金流程 |
| PvP | 战场或竞技场、如何部署 | NPC对手、等级条件、地图/阵容 | 配置、准备、开始 | 现有20级战场、60级竞技场；不是玩家实时匹配 |
| 战报/战利品 | 为什么输赢、拿什么、是否重试 | 真实伤害/治疗/死亡、技能明细、掉落与容量 | 查看记录、展开成员、拾取 | 不以示意 DPS 冒充结算数据 |
| 账号/连接状态 | 切角色、恢复连接、处理后台活动 | 当前角色、过期/失败、进行中的后台任务 | 重试、登录、切换、召回 | 本轮独立试玩不模拟登录和服务端断线 |

## 视觉方向与统一规则

尚未收到独立参考图。依据上一版已运行界面、本地 Classic 图标与 portrait/quest 资源形成暂定方向；不宣称复刻某张未提供的图。

- 借鉴原版单位框架的头像＋血蓝、金色 !/? 任务语义、方形技能图标、暗底细金属框、羊皮纸任务阅读区。
- 界面直接进入场景与当前委托；不出现 Logo、装饰性顶栏、常驻金币栏、汉堡菜单、面包屑或章节大标题。
- 桌面主次比例：场景为主，右侧固定阅读宽度的委托；任务与状态对应当前行为，不在四周铺等宽统计卡。手机先看状态与场景，任务和操作紧随其后，可正常纵向滚动。
- 字体：中文标题 Songti SC/SimSun，正文 PingFang SC/Microsoft YaHei；数字使用等宽数字特性。正文13–14px，辅助11–12px，当前地点/任务18–22px。避免超小金色字铺满屏。
- 间距统一4/8/12/16/24/32；交互目标至少36px，移动端44px。长名称自然换行或可展开，不靠缩小字号。
- 颜色：旧金用于选中/主操作，绿为生命/成功，蓝为法力，红为危险/失败，灰为不可用；品质色只用于物品。羊皮纸必须使用深色正文。
- 边框：主面板1px旧铜线，动作按钮双层浅浮雕；不加无信息意义的徽章、花纹和横幅。
- 状态：选中边框＋文字标记；禁用说明原因；操作中显示具体命令并阻止重复提交；成功在局部显示并更新权威数据；失败保留当前界面并允许重试；空状态说明下一步。
- 组件复用：WorldScene/CharacterModel、Battle embedded、CreaturePortrait、ItemDisplay、DamageMeter、GameSelect、Radix Dialog（重设皮肤及焦点恢复）。不修改原组件库默认皮肤去影响全站。
- 新版模拟与 view/project 均在 Worker 内；页面只收快照、发指令。探索与战斗演出沿用既有资源，不使用整张 UI 效果图。
