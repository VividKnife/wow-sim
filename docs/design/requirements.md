# wow-sim：需求记录

状态：首版设计已获用户确认；完整实现规格见文末链接。数据导入和实现完成情况另行记录。

## 已确认要求

- 网页游戏，适配手机，以 2D 界面交互呈现世界，不构建实际 3D 世界。
- 初期以魔兽世界 60 级经典旧世为内容基础，尽可能复刻该版本的游玩流程、核心乐趣与数值。
- 复刻对象包括伤害公式、物品、角色、技能、副本和怪物；数值准确性是核心要求。
- 初期支持五人队伍；玩家主玩一个角色，可招募等级、装备水平相似的队友。
- 技能通过玩家配置的优先级自动释放。
- 抵达目标地点后，可以挂机杀怪并自动使用食物、饮水等恢复生命和法力。
- 地点之间的地面旅行需要时间，支持飞行点解锁与坐骑系统。
- 用户优先接受当年怀旧服首发版本，并授权根据公开数据的丰富程度选择最容易验证的 60 级版本。
- 用户已选择离线方案 A：离线继续旅行、野外杀怪与补给；副本需要在线开始和推进。

## 已选版本方向

- 目标体验与规则：2019 年 WoW Classic 首发阶段；内容基准为 Phase 1。
- 基础资料：1.12 系列数据、2019 年怀旧服官方说明与可复核测试相互补充。1.12 数据是参考来源，不自动等同于怀旧服实际行为。
- 冲突裁决：有对应首发版本证据时，以该证据为准；缺少证据时保留未验证状态，不静默引入其他版本规则。
- 阶段限制：已有物品的属性版本与物品是否开放分别记录；不能把数据库中全部物品直接加入首发掉落。
- 这是产品基准选择，尚未完成数据导入。具体客户端构建号、服务器热修截止点、源仓库提交和数据文件校验值将在数据清单中固定后，才能称为可复现的数值基准。
- Phase 1 表示内容边界，不要求首个可玩版本实现该阶段的全部内容；初期仍优先练级与五人副本。

## 设计原则与实现约束

### 版本与准确性

- 按上面的 2019 年首发怀旧服方向建立版本清单；不能仅以“60 级”识别数据版本。
- 游戏规则版本与内容开放范围分别记录；第一版只实现有限区域和五人副本，不代表开放全部满级内容。
- 所有数据和公式记录适用版本、来源、验证状态；明确区分已验证、待验证与临时估计。
- 客户端数据、官方说明、可复核的实测和社区实现交叉核查；不把社区服务器实现视为官方真值。
- 固定值、计算公式、随机分布与遭遇行为分别验证，不以平均伤害接近替代机制一致。
- 2D 空间抽象与自动操作属于交互改编，应与已验证的原版规则分开记录。

### 旅行

- 地图由地点与实际可通行路线组成；地面耗时基于路线长度和有效速度计算。
- “步行”暂理解为玩家所说的普通地面赶路，原版走路与跑步的速度差异仍需明确。
- 坐骑影响适用路段的速度；骑乘资格、费用、施放与区域限制遵循最终选定补丁。
- 飞行点记录是否发现，航线记录连通条件、费用和实际航程时间，不按地面直线距离计算。
- 可预设抵达后开始指定活动；旅行与挂机使用同一时间线，避免重复计算收益。
- 地面路线风险如何抽象、是否加入船只等定时交通，尚待进一步设计。

### 小队与挂机

- 暂按玩家单角色加四名 AI 队友理解五人队伍，尚未确认真人联机需求。
- 建议队友招募时匹配实力，招募后保留身份、装备和成长记录。
- 技能策略建议支持条件与优先级，并提供职业默认配置。
- 离线活动范围已确认采用方案 A；结算使用独立于网页后台运行的时间线。

## 已确认首版范围

用户已确认 [首版设计](../superpowers/specs/2026-09-15-wow-sim-first-playable-design.md)：人类法师 1—20 级、北郡至西部荒野的成长旅程、四名 AI 队友和死亡矿井；具体离线、死亡及副本断线规则按该设计执行。
