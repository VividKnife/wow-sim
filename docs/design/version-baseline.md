# 版本基准与公开资料评估

调研日期：2026-09-15。状态：版本方向已选择；来源已发现，尚未完成逐项数据审计。

## 决定

以 2019 年 WoW Classic 首发阶段作为 wow-sim 的目标，内容边界采用 Phase 1。使用 1.12 资料辅助实现，在存在差异时以对应目标版本的证据校正。

用户授权优先采用当年怀旧服首发版，或公开资料更丰富的 60 级版本。当前找到的官方说明、社区数据库和战斗研究足以支持继续沿首发怀旧服方向设计；没有开展全网资料数量统计，因此不声称某一版本的公开数据绝对最多。

## 决策依据

1. 暴雪说明 Classic 使用 1.12 作为开发基础。
2. 暴雪说明职业设计和已有物品属性采用 1.12 状态，但新增物品随内容阶段开放。因此属性版本与可获取阶段必须分别处理。
3. CMaNGOS Classic-DB 提供面向 1.12 的公开内容数据库，可以辅助整理世界数据，但不是怀旧服官方数据库。
4. ClassicSim 提供面向 Classic 的事件驱动战斗模拟、规则说明与测试代码，可以用于交叉检查。其机制仍有待修复的问题，不能直接作为准确性证明。

## 进入实现前的数据要求

- 每条引入的数据应能追溯到具体文件、记录 ID 或文档段落，以及来源版本或日期。
- 固定客户端构建号与服务器热修截止点；仅有客户端版本不能唯一确定服务器规则。
- 对仓库来源固定提交，对文件记录校验值，保留转换和覆写记录。
- 来源冲突应记录候选值、证据与取舍，不按较方便的值合并。
- 验证状态至少区分：已验证、参考实现、估计、未知。
- 数据库覆盖与实际玩法实现覆盖分别统计；拥有一条技能记录不代表该技能机制已经实现。
- 战斗分为固定数值、公式、概率与时间顺序验证；旅行分为路线长度、速度、航线时间和限制条件验证。
- 公开掉落统计不自动等于官方精确概率；缺失的服务端脚本、刷怪和路线细节保留证据缺口。

## 首个可玩版本的原则

采用少量区域、职业和一个五人副本形成完整旅程，优先做到已覆盖机制可核查。世界旅行、坐骑和飞行点沿用同一版本规则。扩大内容时继续沿用同一来源与验证流程。
